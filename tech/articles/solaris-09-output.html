書き出しとワークフローへの組み込み

houdini-solaris / 2026-08-19

出典: SideFX 公式ドキュメント Writing out USD / USD ROP / husk。 このページは上記を日本語で要約・再構成した学習メモです。 パラメータ名と挙動は Houdini 22.0.368 の実機で確認しています。シリーズ最終回です。

この記事で扱うこと

  • Save Style の4つ — 同じシーンでも、出てくるファイルの数と形が変わります
  • どのレイヤーがどのファイルになるか
  • アニメーションの書き出しと、メモリが足りなくなったときの逃げ道
  • husk でのバッチレンダリング
  • 既存のワークフローに、どこから Solaris を差し込むか

出口は2つある

第0回に書いたことをもう一度。Solaris の出口は2つです。

出口使うノード出るもの
USD を書き出すusd_rop（USD ROP）.usd ファイル群
画像を出すusdrender_rop / karma.exr など

名前が似ていて紛らわしいので、もう一度書いておきます。 usd_rop はファイル、usdrender_rop は絵です。

Save Style — 同じシーンでも出方が変わる

USD ROP でいちばん重要なパラメータがこれです。 合成された結果は変わりません。変わるのは、ファイルが何個できるかだけです。

Save Styleひとことで使いどころ
Flatten Implicit Layers（既定）名前のないレイヤーだけ畳むふだんはこれ
Flatten All Layersサブレイヤーを全部畳む持ち出し用に枚数を減らしたいとき
Separate Layers全部バラバラ「どのノードが何を書いたか」を見たいとき
Flatten Stage合成を焼き込んで1枚履歴を消して渡したいとき

Flatten Stage だけは性質が違います。他の3つは合成の構造（参照・バリアント）を保ちますが、 Flatten Stage は焼き込みます。選ばれなかったバリアントは消えます。 第4回で作った「色違いを持ったアセット」も、1つの姿に固定されてしまいます。

「1ファイルにまとめたいけれど、履歴は残したい」という場合は、 Flatten Stage ではなく usdzip で .usdz にする、という手があります。 中身は複数ファイルのままで、外側が1つのアーカイブになります。

どのファイルがどこに出るか

ルールは2つだけです。

対象出力先の決まり方
ルートレイヤーUSD ROP の Output File（lopoutput）
保存パスを持つレイヤーそのレイヤーの Save Path

Save Path を付けるのが、第2回で出てきた configurelayer です。 sopimport と sopcreate にも Save Path のパラメータがあります。

パスは $HIP/props/lamp.usd のように絶対パスで書くのが推奨されています。 書き出すときに Use Relative Paths という出力プロセッサが既定で動いていて、 ファイル間の参照を相対パスに書き換えてくれるからです。 そのおかげで、あとからフォルダごと移動しても壊れません。

Strip Layers Above Layer Breaks

第2回の Layer Break が実際に効くのは、このチェックボックスがあるからでした。

設定結果
オン（既定）Layer Break より前は書き出されません
オフLayer Break を無視して、全部書き出します

オフにできるのが親切なところです。 ふだんは差分だけ納品して、たまに「確認用にシーン全部が入ったファイルが欲しい」というとき、 ネットワークを組み替えずにチェック1つで切り替えられます。

アニメーションを書き出す

フレーム範囲を書き出すときに知っておきたいのが Flush Data After Each Frame です。

設定動き向いている場面
オフ（既定） 全フレームをメモリに溜めて、最後に一気に書く ふつうのカット
オン 1フレームごとにディスクへ書く メモリが足りないとき。大量のデータ

書き出し中にメモリを使い切ってしまう、というのはよくある詰まり方です。 そのときはこれをオンにすると、常に1フレーム分しかメモリに載らなくなります。 そのぶん遅くなり、ファイルも少し大きくなりますが、書けなかったものが書けるようになります。

オンにしたうえで出力パスに $F4 を入れると、フレームごとに別ファイルになります。

$HIP/usd/scene_$F4.usd

この形で出したあと、usdstitchclips でまとめる、というのが大きなシーンの定番のようです。

Track Primitive Existence to Set Visibility も覚えておくと役に立ちます。 フレームによってプリムが出たり消えたりするシーンを1つのファイルにまとめると、 全フレームのプリムが合体してしまいます。これをオンにすると、 出入りを可視性のアニメーションとして書いてくれます。

画像を出す — husk

画像側の出口は usdrender_rop で、その裏で動いているのが husk です。 .usd を受け取って絵にする、コマンドラインのプログラムです。

ここがワークフロー的にいちばん効いてくるところだと思います。 husk は Houdini の GUI を必要としません。つまり、

  1. Houdini で .usd を書き出す
  2. その .usd をレンダーファームに配る
  3. 各マシンで husk が絵にする

という分業ができます。シーンの組み立てとレンダリングが、 .usd というファイル1つで完全に切り離せる。 これは .hip を配る運用とはかなり性格が違います。

どこから Solaris を差し込むか

ここまで書いてきて、最後に「で、明日から何をすればいいのか」という話をしておきます。 いきなり全部を Solaris に移すのは大変なので、3段階に分けるのがよいかなと思っています。

第1段階 — レンダリングだけ置き換える

やることsceneimport か sopimport で既存の /obj を持ち込み、Karma で出す
覚えるもの第0回・第1回・第6回・第7回
得られるものビューポートと最終レンダリングが同じになる

USD のことはほとんど知らなくても済みます。 まずここまでで一度回してみるのが、いちばん挫折しにくいと思います。

第2段階 — アセットを USD で持つ

やることよく使うモデルを .usd で書き出し、reference で配置する
覚えるもの第2回・第3回・第4回
得られるもの同じものを何度置いても重くならない。直せば全部直る

ここで初めてレイヤーとリファレンスが必要になります。逆に言うと、 第1段階では要りません。必要になってから覚えれば十分です。

第3段階 — 分業する

やることLayer Break で担当範囲を切り、差分だけを .usd で納品する
覚えるもの第2回・第9回（この記事）
得られるもの他の人の作業を壊さずに、自分の変更だけを渡せる

1人で作業しているうちは要りません。 人が増えたとき、あるいは過去の自分と分業したくなったときに効いてきます。

検証機についての注意

このシリーズは Apprentice ライセンスの Houdini 22.0.368 で検証しました。 書き出しまわりには、そこから来る制約が2つあります。

項目Apprentice（検証機）
USD の書き出し.usdnc になる。テキストとして読めない
画像の解像度上限あり。ウォーターマークが入る

ノード名・パラメータ名・既定値・レイヤーの構造といった、このシリーズで扱ったことには影響しません。 ただ、他の DCC やレンダーファームに .usd を渡す運用を組むなら、 そこは本番ライセンスで一度確認してください。ここだけは検証機では確かめられませんでした。

シリーズのまとめ

#いちばん言いたかったこと
00ステージは空っぽ。ジオメトリ・ライト・カメラ・karma の4つで絵は出る
01USD の階層は SOP 側のアトリビュートで決まる。LOP では直せない
02Layer Break は見た目を変えない。変わるのは書き出したときだけ
03プリムパターンを1回覚えると、以降のノードが全部楽になる
04リファレンスはコピーではなくリンク。1か所直せば全部直る
05マテリアルは箱、シェーダは中身。迷ったら MaterialX
06カメラは常に Y up・−Z 向き。パラメータと USD の数字は違う
07karma LOP は4つの詰め合わせ。Var → Product → Settings の入れ子
08Quality は本数ではなく倍率。症状を見てから触る場所を決める
09Save Style で出方が変わる。Flatten Stage だけは履歴が消える

Solaris が複雑に見えるのは、たぶん「難しいものが1つある」のではなく、 性質の違うものが同時に見えているからだと、書き終えてみて改めて思いました。 1つずつなら、どれもそんなに大きくありません。
