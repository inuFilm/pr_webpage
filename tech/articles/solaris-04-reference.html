リファレンスとバリアント — アセットを組み合わせる

houdini-solaris / 2026-08-19

出典: SideFX 公式ドキュメント Reference / Add Variant / Set Variant / LOPs and USD glossary。 このページは上記を日本語で要約・再構成した学習メモです。 リファレンスとバリアントは Houdini 22.0.368 の実機で組んで、切り替わることを確認しています。

この記事で扱うこと

  • SubLayer と Reference の違い — 重ねるのかぶら下げるのか
  • バリアント — 1つのアセットに複数の姿を持たせる仕組み
  • 実機で棚に2つ並べて、上流を1か所いじると両方とも変わることを確認します
  • reference / addvariant / setvariant のノード解説

コピーではなく、リンクです

シーンに椅子を10脚並べたい、というときの話です。

ふつうの発想だと「椅子のデータを10個複製する」ですが、USD ではそうしません。 椅子は1つだけ置いて、10か所から「あれを見て」と指を差すという作り方をします。

これがリファレンスです。ウェブページのリンクと同じで、実体は1つ。 だから元の椅子を直せば、10脚ぜんぶが直ります。ファイルも重くなりません。

SubLayer と Reference の違い

外から USD を持ち込む方法は2つあって、ここが最初の分かれ道です。

SubLayerReference
ひとことで重ねるぶら下げる
出てくる場所ファイルに書かれていたパスのまま自分で指定したパスの下
同じものを複数できないできる
向いている場面シーン全体を持ち込む。他部署のレイヤーを載せるアセットを配置する。同じものを何度も使う

「シーンを持ち込む」なら SubLayer、「モノを置く」なら Reference、と覚えておけばだいたい合っています。

Merge LOP は「メモリ上のステージ版の SubLayer」、Graft Stages LOP は「メモリ上のステージ版の Reference」という関係になっています。 ファイル相手か、ノードチェーン相手かの違いですね。

バリアント — 1つのアセットに複数の姿

もう1つがバリアントです。同じアセットの色違い、LOD 違い、開いた／閉じた、といった 複数の姿を1つのプリムに入れておいて、あとから1つだけ選ぶ仕組みです。

用語が2段になっているので、そこだけ先に整理します。

バリアントセット選択肢のグループ。例: model、color
バリアントその中の1つ。例: var_hi、var_lo

1つのプリムにバリアントセットを複数持たせられるので、 「形は hi、色は red」のような組み合わせもできます。

実機で組んでみました

球と立方体を2つのバリアントにして /asset にまとめ、それを2か所からリファレンスしました。

結果

バリアントの選択を var_hi から var_lo に変えたときの、ステージの変化です。

プリムvar_hi のときvar_lo のとき
/asset/geoSphereCube
/shelf/copy1/geoSphereCube
/shelf/copy2/geoSphereCube

触ったのは setvariant のパラメータ1つだけです。 コピーを配ったのではなくリンクを張ったので、こうなります。

合成アークが見えます

/shelf/copy1 が何でできているかを問い合わせたら、こう返ってきました。

Root       →  /shelf/copy1
Reference  →  /asset
Variant    →  /asset{model=var_lo}

USD の「合成」というのは、この3行が積み上がることでした。 自分の場所があって、そこにリファレンスが刺さっていて、その先でバリアントが1つ選ばれている。 言葉で読むと難しいのですが、並べて見ると仕組みは素直です。

実機で気づいたこと — バリアントの中身は「何を入れるか」で決まる

最初、思ったとおりに動きませんでした。setvariant で var_lo（立方体）を選んでいるのに、 /asset はずっと Sphere のままだったんです。

原因は addvariant の Variant Source Primitive（variantprimpath）でした。 ここを /geo にしていたので、プリムの中身だけがバリアントに入り、 型そのものはバリアントの外に書かれていました。

書き出されたレイヤーを読んだら一目瞭然でした。

def Sphere "asset" (                 ← 型は外側。最初の入力のものに固定
    variants = { string model = "var_lo" }
    prepend variantSets = "model"
)
{
    variantSet "model" = {
        "var_hi" { double radius = 1  ... }   ← 球の属性だけ
        "var_lo" { double size   = 2  ... }   ← 立方体の属性だけ
    }
}

Variant Source Primitive を既定の / に戻したら、期待どおりになりました。

/asset          (Xform)      ← 器
└─ geo          (Sphere / Cube)  ← ここが丸ごと入れ替わる
Variant Source Primitiveバリアントに入るもの結果
/geo属性だけ型が切り替わらない
/（既定）プリムごと丸ごと切り替わる

コツは「バリアントの中身は、どれを選んでも同じ形をしているほうがよい」ということだと思います。 公式ドキュメントも「後から上書きする予定があるなら、各バリアントの構造をそろえておくとよい」と書いています。 入れ替わるのは中の子プリム、器は共通、という作りにしておくと事故が減ります。

ノードごとの解説

Reference reference

やること別の場所のプリムツリーを、指定したパスの下にぶら下げる
入力0〜多数。1つ目＝置き先のステージ、2つ目以降＝参照元
参照元ファイル／別のノードチェーン／同じツリーの中の別のプリム
Reference Typefile / payload / prim / inherit / specialize
ActionCreate New Primitives（新規）／ Edit Existing Primitives（既存に足す）
Primitive Count1つの設定から複数個作れます。名前に連番が付きます

今回は Primitive Count = 2 にして、/shelf/copy1 と /shelf/copy2 を一度に作りました。

パラメータの上部にタブが2つあります（マルチ入力用と、ファイル／内部参照用）。 どちらのタブがアクティブかで使われる設定が変わるので、 「値を入れたのに何も出てこない」ときはタブを確認してみてください。実際に一度これで詰まりました。

Payload — 読み込みを後回しにする

Reference Type に payload があります。リファレンスとほぼ同じですが、 中身の読み込みを遅らせられるのが違いです。

ReferencePayload
読み込み常にオン／オフできる
既定—Houdini では全部読み込む
使いどころ普通のアセット配置巨大なシーン。街1つ、森1つ

読み込まないようにすると軽くなりますが、そのぶん 中のプリムがシーングラフに出てこなくなり、プリムパターンにも当たらなくなります。 前回のパターンの話と直結するので、切るときは意識しておくとよさそうです。

Add Variant addvariant

やることバリアントセットを作り、そこにバリアントを追加する
入力1つ目＝本流のステージ、2つ目以降＝各バリアントの中身
要のパラメータprimpath（既定 /$OS）、variantset（既定 model）、 variantprimpath（既定 /）
バリアント名指定しなければ入力ノードの名前が使われます
プリムが無ければ作ります（型は parentprimtype、既定 UsdGeomXform）

今回、バリアント名を何も指定しなかったので var_hi / var_lo（＝ノード名）になりました。 ノード名がそのまま USD に残るので、入力ノードの名前は意味のあるものにしておくと後で楽です。

Set Variant setvariant

やることバリアントセットの中から1つ選ぶ
入力1（必須）
要のパラメータプリムパターン、variantset、variantname
複数まとめてNumber of Variants を増やすと、1ノードで何組でも選べます
ランダムに選ぶChoose Variant Name by Index ＋ rand() の式

気をつけたいのが、存在しないバリアント名を書いても警告もエラーも出ないことです。 選択が黙って解除されるだけになります。前回の「綴りを間違えても0個」と同じ手触りですね。

Explore Variants explorevariants

やることバリアントの組み合わせを並べて一覧表示する
向いている場面作ったバリアントの確認。カタログ画像を作りたいとき

詰まりやすいポイント

  • バリアントを切り替えても形が変わらない → addvariant の Variant Source Primitive を確認します。 既定の / のままにしておくのが基本です。
  • Set Variant が効かない → バリアント名の綴りです。エラーは出ません。
  • Reference で何も出てこない → パラメータ上部のタブが、使いたい入力方法と合っているか。
  • Payload を切ったら選べなくなった → 仕様です。読み込んでいないプリムはパターンに当たりません。
  • バリアント名が sphere1 のような機械的な名前になる → 入力ノードの名前がそのまま入ります。 先にリネームしてから繋ぐと綺麗です。
