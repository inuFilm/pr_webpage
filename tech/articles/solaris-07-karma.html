Karma を回す — 4つの詰め合わせを分解する

houdini-solaris / 2026-08-19

出典: SideFX 公式ドキュメント Karma LOP / Render Var / Render Product / Karma User Guide。 このページは上記を日本語で要約・再構成した学習メモです。 できるプリムの構造と AOV の一覧は Houdini 22.0.368 の実機で確認しています。

この記事で扱うこと

  • karma LOP が4つのノードの詰め合わせであること、その内訳
  • Render Settings / Render Product / Render Var がそれぞれ何を決めているか
  • CPU と XPU の切り替え
  • AOV の出し方（実機で標準セットを作って中身を確認しました）

karma LOP を開けると4つ入っている

第0回で少しだけ触れたところを、ここできちんと分解します。 公式ドキュメントの説明はこうです。

Karma LOP は Render Vars / Render Product / Karma Render Settings / USD Render ROP の機能を 1つにまとめたもので、Karma 固有の設定も含めて1か所で構成できるようにしたノードです。

つまり karma LOP を1個置くというのは、4つのノードをまとめて置いているのと同じです。 そして置いた瞬間に、ステージに /Render という枝ができます。

3つのプリムの役割

名前が似ていて混乱しやすいので、一言ずつで区別しておきます。

プリムひとことで決めること
RenderVar 何を 1枚の画像に入る1種類のデータ。ビューティ、深度、法線、Cryptomatte など
RenderProduct どこへ RenderVar を集めて1つのファイルにする。パスと形式
RenderSettings どう計算するか カメラ、解像度、サンプル数、エンジン。Product をどれ使うかも

入れ子で覚えると簡単です。Var が集まって Product になり、Product を Settings が束ねる。 料理でいうと、Var が材料、Product が皿、Settings がレシピですね。

Pixar の仕様では、これら3種類のプリムは /Render の下に置くことになっています。 レンダリング側がツリー全体を探し回らなくて済むようにするためです。 Houdini の既定値がそうなっているのは、この決まりに従っているからでした。

CPU と XPU

切り替えは Engine Settings（内部名 engine）ひとつです。実機で確認した既定は cpu でした。

Karma CPUKarma XPU
速度遅い速い
機能多い。挙動もより正確CPU を追いかける形で、いくらか少ない
サンプル数のパラメータsamplesperpixel（既定 9）pathtracedsamples（既定 128）
マテリアルMaterialX / Principled / USD PreviewMaterialX / USD Preview のみ
GPU の条件—現状 NVIDIA のみ

サンプル数のパラメータが2つ並んでいて、エンジンによって使われる方が変わるのが罠です。 CPU なのに Path Traced Samples をいくら上げても何も変わりません。 逆もまた然りです。ここは第8回でもう一度扱います。

AOV を出す

AOV（追加の画像プレーン）を足す方法は3通りあります。

やり方手間向いている場面
karmastandardrendervars を置く1ノードまず定番を全部出したいとき
additionalrendervars を置くチェックを入れる定番から少し足したいとき
rendervar を1つずつ置く細かいLPE で自分で定義したいとき

標準セットの中身（実測）

karmastandardrendervars を1つ置いたら、これだけできました。

/Render/Products/Vars/
├─ beauty                     ビューティ
├─ combineddiffuse            ディフューズ
├─ combinedglossyreflection   反射
├─ combinedvolume             ボリューム
├─ hitPz                      深度
├─ hituv                      UV
└─ hitN                       法線

コンポジットでよく使うものが一通りそろっています。 まずこれを置いて、足りないものだけ足す、という順番が楽だと思います。

自分で作るとき

rendervar を使うときに決めるのは、基本この3つです。

パラメータ意味
Data Type（既定 color3f）データの型。EXR のチャンネル名がこれで決まります
Source Name何を取ってくるか
Source TypeSource Name の読み方。Raw / Primvar / LPE

Data Type が地味に効きます。color3f なら EXR のチャンネル名は R/G/B、 normal3f なら x/y/z になります。 コンポジット側でチャンネルが見つからないときは、まずここを疑うとよさそうです。

LPE（Light Path Expression）を選ぶと、光の経路を式で指定できます。 「このライトからの直接光だけ」「2回反射した成分だけ」といった切り出し方ができるもので、 Karma の AOV の本領はここにあります。

ノードごとの解説

Karma karma

やることレンダリングの設定と実行を1か所でまとめる
入力1〜2（最低1つ必要。generator ではありません）
パラメータ数80（Houdini 22.0.368 実測）
出力設定済みの USD ステージ。下流にもう1つ LOP を繋げます

ここは見落としやすいところですが、karma LOP は行き止まりではありません。 出力はステージなので、下流でさらに編集したり、そのまま .usd に書き出したりできます。 「レンダリング設定を含んだシーン」を納品する、という使い方ができるわけです。

パラメータ既定値
Camera（camera）/cameras/camera1
Resolution（resolution）1280 × 720
Output Picture（picture）$HIP/render/$HIPNAME.$OS.$F4.exr
RenderSettings Primitive Path（primpath）/Render/rendersettings
Engine Settings（engine）cpu

$F4 は4桁ゼロ埋めのフレーム番号です。連番で出すなら必ずこれを含めます。 忘れると、全フレームが同じファイルに上書きされていきます。

Karma Render Settings karmarendersettings

やることレンダリング設定のプリムだけを作る
既定の書き込み先/Render/$OS（karma LOP は /Render/rendersettings）
向いている場面設定だけを別レイヤーで管理したいとき。分業するとき

Render Product renderproduct

やること複数の RenderVar を1つのファイルにまとめる
決めること出力パス、形式、どの RenderVar を含めるか
向いている場面ビューティとデータ系を別ファイルに分けたいとき

USD Render ROP usdrender_rop

やることステージを実際にレンダリングする（画像を出す）
裏で動くものhusk。USD を絵にするコマンドラインツール
向いている場面ファーム投げ、バックグラウンドレンダリング

名前が似ている usd_rop（USD ROP）とは役割が違います。 usd_rop は .usd ファイルを書き出すもの、 usdrender_rop は 画像を出すものです。第2回で使ったのは前者でした。

実機で気づいたこと

checkpoint という Product が最初から付いてくる

karma LOP が作るプリムを数えたら、RenderProduct が2つありました。 renderproduct と checkpoint です。

チェックポイントは、長いレンダリングの途中経過を保存して、 中断しても続きから再開できるようにする仕組みです。 使わないつもりでも最初から用意されている、ということですね。

Apprentice には解像度の上限がある

検証機は Apprentice なので、出力解像度は 1280×720 が上限で、 書き出した画像にはウォーターマークが入ります。 既定の解像度がちょうど 1280×720 なのは、そのままでは引っかからないようにするためかもしれません。

Indie ではこの上限が上がります（本番の数字はライセンス側で確認してください）。 4K で出す前提のワークフローを組むなら、ここは検証機では確かめられません。

詰まりやすいポイント

  • 全フレームが同じファイルに上書きされる → 出力パスに $F4 が入っていません。
  • サンプルを上げても変わらない → エンジンと対応していないほうを触っています。 CPU は samplesperpixel、XPU は pathtracedsamples。
  • AOV が EXR に入っていない → RenderProduct に含める設定になっているか確認します。 RenderVar を作っただけでは出ません。
  • チャンネル名が想定と違う → RenderVar の Data Type で決まります。
  • karma LOP の下流に何も繋げないと思っていた → 出力はステージです。繋げます。

次回

回るようになったので、次はノイズを減らす回です。 サンプリングのパラメータがたくさんあって、どれがどのノイズに効くのか分かりにくいところを、 種類ごとに整理します。「とりあえず全部上げる」から抜け出すのが目標です。
