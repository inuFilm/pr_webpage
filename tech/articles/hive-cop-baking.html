誰の講演か

SideFX の image processing TD で Copernicus チーム所属です。 つまり Bake Pre-Process を作った当事者の解説になっています。

タイトルは "Baking Only Fans"。扇風機アセットを使うのでダジャレになっています。

話の流れ

時刻内容
03:23前リリースのケージメッシュモードの話。cage offset などのカスタマイズがあり、 結果もライブ更新されていた。しかし大きな問題があった（前リリースのローンチデモの映像で示されます）
06:44Bake Pre-Process のインターフェース全体の解説。 その後ハイテク扇風機アセットで実演

13:25Q&A: Match Pieces by Name について

ビューポートのライティングがおかしく見える理由

10:04 あたりで、プレビューマテリアルの見た目が変に見える場面があります。 これには理由があってこう説明されています。

これは Unreal 向けに作られていて、法線がビューポートや Copernicus の想定と違うから。

つまりバグではなく、書き出し先に合わせた法線の向きです。 Houdini のビューポートで確認するときに戸惑うところですが、 Unreal に持っていけば正しく見えます。

「どこで見るか」で正しさが変わるという話なので、 ゲーム向けにベイクするなら知っておいたほうがよさそうです。

Match Pieces by Name（Q&A で出てくる要点）

インターフェースの最下部にあります。

low res と high res に一致する name アトリビュートを持たせておけば、自動で対応付けられます。

これは実務でかなり効くと思います。パーツが多いアセットで、 どのハイポリがどのローポリに対応するかを手で指定するのは面倒です。 命名を揃えておくだけで済むなら、モデリング側の作法として決めておく価値があります。

Summon VFX の第3回でも 「Vellum Drape のシーム対応は名前で指定するので、命名が雑だと詰む」という話が出ていました。 Houdini では命名がそのまま自動化の入口になる場面が繰り返し出てきます。

ハウツーとの関係

Karma でテクスチャをベイクする回で Bake Pre-Process を実際に使う手順を扱っています。

あちらでは触れられていない Match Pieces by Name がこの講演の Q&A で出てくるので、 両方見る価値があります。手順はハウツー、設計の意図と細かい仕様はこの講演、という読み分けです。

この講演から持ち帰るもの

  • 講演者は Bake Pre-Process を作った本人です。仕様の理由が分かる講演になっています
  • 前リリースのケージメッシュモードには大きな問題があったという前提から入ります
  • プレビューでライティングが変に見えるのは、Unreal 向けの法線だからです。バグではありません
  • Match Pieces by Name: low res と high res に同じ name アトリビュートを持たせれば自動で対応付けられます
  • Houdini では命名がそのまま自動化の入口になる、という一般則の一例です
