COP のノード — テクスチャを作る道具

houdini-nodes / 2026-08-19

出典: SideFX 公式ドキュメント Copernicus (Houdini 公式) / COP nodes / Texture baking。 このページは上記を日本語で要約・再構成した学習メモです。ノード名とパラメータ名は Houdini 22.0.368 の同梱ヘルプと実機で照合しています。

この記事で扱うこと

  • COP を流れているものがレイヤーであること
  • 生成・色・フィルタ・変形・合成・PBR を1ノードずつ
  • タイリングと法線の向き、書き出しの色空間の落とし穴

COP を流れているのは「レイヤー」

SOP がジオメトリを流すように、COP はレイヤー（名前つきの画像）を流します。 1本の線に複数のレイヤーが乗っていて、ノードは名前で選んで処理します。

Copernicus はGPU で走ります。ノードを繋いだ結果がその場で更新されるので、 数値を振りながら見た目を決める作業に向いています。

テクスチャを作るときの並び

段やること代表ノード
1. 生成模様のもとを作る fractalnoise / worleynoise / ramp
2. 加工コントラスト・ぼかし・歪み remap / blur / distort
3. 合成重ねる・マスクで混ぜるlayer
4. PBR 化高さから法線、AO、曲率 heighttonormal / curvature
5. 書き出しファイルにするrop_image

1. 入口と出口

File file

やること画像ファイルを読み込む
使いどころ既存のテクスチャを持ち込むとき

公式リファレンス（英語）

ROP Image Output rop_image

やることレイヤーを画像ファイルに書き出す
使いどころ出口。PBR マップ一式もここから出す
入力0〜1
要のパラメータcopoutput — 出力ファイルのパス（既定 $HIP/comp/$HIPNAME.$OS.$F4.exr）
colorconversion — 書き出す色空間（既定 0）
aov# — 書き出すレイヤーの名前
addaovs — 複数のレイヤーをまとめて出す
注意colorconversion を raw にしないと二重にエンコードされます。ACES の設定下では、リニアのまま出したいマップ（法線・粗さ・高さ）が色変換を通ってしまい、値がずれます（実測）。パスに <LAYER> を入れると、レイヤーごとに別ファイルで一括書き出しできます。

ここが Copernicus をゲームアセットに使う理由です。

やることハイポリからローポリへ、法線・AO・曲率などを焼く

入力0〜5

詰まりやすいところ

症状まず見るところ
書き出した画像の明るさがおかしい rop_image の colorconversion。 リニアで出したいものは raw
タイルの継ぎ目が出る ノイズ側の dotiled。生成の段で決める
タイルの繰り返しが目立つ hextile、または uvxform でタイル数を上げて模様を小さく見せる
法線マップの凹凸が逆 convertnormal で Y を反転（OpenGL ↔ DirectX）
焼いた法線が真っ黒 接線の設定。bakegeometrytextures の既定を疑う
合成すると縁が黒く縁取られる premult。アルファの掛かり方が食い違っている
数値は合っているのに見た目が違う 等倍で縁をまたいでクロップして目視する。 統計値だけでは継ぎ目を見逃します
