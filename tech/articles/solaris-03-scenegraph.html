シーングラフを読む・選ぶ — プリムパターンの5段階

houdini-solaris / 2026-08-19

出典: SideFX 公式ドキュメント Primitive matching patterns / Scene Graph Tree pane / Configure Primitive / Collection。 このページは上記を日本語で要約・再構成した学習メモです。 パターンの一致結果は Houdini 22.0.368 の実機で1つずつ評価して確認しています。

この記事で扱うこと

  • Scene Graph Tree と Scene Graph Details の役割の違い
  • プリムパターン — Solaris のほぼ全ノードで使う「どのプリムに効かせるか」の書き方
  • 実機で13種類のパターンを評価して、何が当たって何が当たらないかを確認します
  • collection / configureprimitive のノード解説

覚えるのはここだけ、という話

Solaris のノードを開くと、上のほうにたいてい Primitives という欄があります。 「このノードをどのプリムに効かせるか」を書く欄です。

これがほぼ全部のノードで共通なので、書き方を1回覚えると、以降のノードが全部楽になります。 逆にここが曖昧なままだと、ノードごとに「なぜか効かない」を繰り返すことになります。 この回だけ少し前のめりに書いておくのは、そのためです。

まず、見る場所が2つある

シーンの中身を確認するパネルは2つあって、役割がはっきり分かれています。

Scene Graph TreeScene Graph Details
見るものプリムの並び1つのプリムの中身
分かること階層、型、Kind、表示・非表示属性の名前と値、どのレイヤーから来たか
使うとき「どこにあるんだっけ」「この値、誰が書いた？」

Details のほうは、第2回のレイヤーの話とつながっています。 1つの属性が複数のレイヤーから来ているとき、どれが勝っているかがここで見えます。 「パラメータを変えたのに反映されない」ときは、たいていもっと強いレイヤーが上にいるので、まずここを見ます。

プリムパターン — 5段階で覚える

いきなり全部覚える必要はなくて、下から順に足していけば大丈夫です。

段書き方例
1パスをそのまま書く/imported/box_geo
2ワイルドカード/imported/* ／ /**/*_geo
3種類で選ぶ（オートコレクション）%type:Mesh ／ %kind:component
4組み合わせる%type:Mesh ^ /imported/**
5名前を付けて使い回す（コレクション）%KeyLights

2段目 — ワイルドカード

記号意味
*名前の中の任意の文字列。階層は跨ぎません
**階層を何段でも跨ぎます
?任意の1文字
[...]カッコの中のどれか1文字。Leg[1234] のように使います

* と ** の違いだけ押さえておけば十分です。 「直下だけ」なら *、「以下ぜんぶ」なら **。

3段目 — 種類で選ぶ

% で始まるのがオートコレクションです。パスを知らなくても、性質で選べます。

書き方選ぶもの
%type:MeshUSD の型で選ぶ
%kind:componentKind（アセットとしての単位）で選ぶ
%descendants(/imported)あるプリムの子孫ぜんぶ
%ancestors(%type:Mesh)あるプリムの親をたどる
%active(false)止められているプリム
%bound(/cameras/camera1)そのカメラの画角に入っているもの

書き方は2通りあって、%kind:component と %kind(component) は同じ意味です。 引数が増えるものは関数の形のほうが読みやすいと思います。

4段目 — 組み合わせる

記号意味例
スペース足す（または）%type:Mesh %type:Camera
&両方に当たるものだけ（かつ）%type:Mesh & %descendants(/imported)
^引く%type:Mesh ^ /imported/**

区切りがスペースで「または」というのが最初つまずくところです。 複数のパスを並べて書くと、それは全部が対象になります。

実機で13種類、全部評価しました

言葉だけだと不安なので、Houdini 22.0.368 に第1回で組んだステージを読ませて、 パターンを1つずつ評価させました。ステージの中身はこうです。

評価した結果がこちらです。数字は一致したプリムの個数です。

パターン数一致したもの
/**17ステージ全部
/imported/*2box_geo sphere_geo
/**/*_geo33つの Mesh すべて（階層を跨ぎました）
%type:Mesh33つの Mesh
%kind:component2/imported /sopcreate_direct
%type:Camera1/cameras/camera1
%descendants(/imported)2box_geo sphere_geo（自分は入りません）
%ancestors(%type:Mesh)2/imported /sopcreate_direct
%type:Mesh %type:Camera4スペースは足し算でした
%type:Mesh & %descendants(/imported)2& はかつ
%type:Mesh ^ /imported/**1torus_geo だけ。^ は引き算
%defined17全部（over だけのプリムは無い状態でした）
%active(false)0止めているものが無いので0

「スペースは足し算」「& はかつ」「^ は引き算」の3つが確認できれば、 4段目まではもう使えます。

実機で気づいたこと

型の名前は「新しいほう」で書いても当たらないことがある

ドームライトを型で選ぼうとして、こうなりました。

パターン結果
%type:DomeLight_11個
%type:DomeLight0個
%type:Light1個

Houdini 22 の Dome Light LOP は、新しい DomeLight_1 というスキーマでプリムを作ります。 古い DomeLight という名前では当たりません。

一方で、基底の型 Light で書けば当たりました。 つまり %type: は継承をたどってくれます。 バージョンによって型名が変わりうるところは、基底の型で書いておくほうが安全そうです。

型の正確な名前は Scene Graph Tree の Type 列に出ています。 迷ったらそこをコピーするのがいちばん確実です。

/Render/** に /Render 自身は入らない

/** ^ /Render/** を評価したら 10 個返ってきて、その中に /Render が残っていました。 ** は子孫だけで、自分自身は含みません。

自分も含めたいときは /Render /Render/** のように並べて書くか、 %descendants(/Render, strict=false) を使います。

無いオートコレクションは、エラーにならず0個になる

試しに %light や %isa:Light と書いてみたところ、 エラーは出ず、静かに0個が返ってきました。

これは地味に怖いところです。綴りを間違えても「何も当たらなかった」としか見えません。 思った数が返ってこないときは、まず綴りを疑うのが早いです。

ノードごとの解説

Collection collection

やることプリムパターンで選んだ集合に名前を付けて保存する
入力0〜1
要のパラメータCollection Name、Primitive Path（既定 /collections）、含める／除外するパターン
呼び出し方%KeyLights（/collections 上なら名前だけ）
向いている場面同じ選択を何度も使うとき。他部署に渡す「窓口」を作りたいとき

覚えておきたいのが Expansion Rule です。

設定意味
No Expansion書いたパスそのものだけ
Expand Primitivesその下の子孫も全部入る

「入れたはずなのに子供が入っていない」はここが原因になりがちです。

コレクションは USD の標準機能なので、書き出したファイルにも残ります。 「このアセットのライトはこれ」を .usd に埋めて渡せる、というのがコレクションの本当の価値だと思います。

Configure Primitive configureprimitive

やることプリムのメタデータをまとめて設定する
入力0〜1
主な設定Kind / Purpose / Visibility / Activation / Instanceable / Draw Mode
チェックボックス第1回と同じで、オンにしたものだけが書き込まれます

ここで押さえておきたいのが Kind と Purpose の2つです。

Kind意味
component1個のアセット。それ以上分解しない単位
groupアセットをまとめたもの
assemblyいちばん外側のまとまり
subcomponentcomponent の中の部品

第1回で sopimport の kindschema の既定が component だったのは、これです。 Kind を付けておくと %kind:component で選べるようになるので、 後の自分のために付けておくもの、と考えると納得しやすいと思います。

Purpose意味
default指定なし。普通に描かれます
render本番用の高解像度ジオメトリ
proxy軽い代役。テストレンダリング用
guideビューポートには出るが、レンダリングには出ない

Purpose を使うと、レンダリング設定側で「render だけ描く」といった切り替えができます。 重いシーンを回すときに効いてくる仕組みです。

Prune prune

やること選んだプリムを隠す、または止める
要のパラメータTarget Rules（複数書けます）、method
method の既定makeinvisible（Make Invisible）
便利な使い方Prune Unselected をオンにすると「これ以外を消す」になります

第2回で踏んだとおり、既定は「隠す」であって「止める」ではありません。 ツリーからも消したいときは deactivate に変えます。

詰まりやすいポイント

  • パターンを書いたのに0個 → 綴り間違いでもエラーにならず0個になります。 まず % の後ろを疑ってください。
  • %type: が当たらない → 型名がバージョンで変わっている可能性があります。 Scene Graph Tree の Type 列をコピーするか、基底の型（Light など）で書きます。
  • ** に自分自身が入っていない → 仕様です。 自分も含めるなら並べて書くか %descendants(..., strict=false)。
  • コレクションに子供が入らない → Expansion Rule が No Expansion のままです。
  • 複数パスを書いたら全部に効いた → スペースは「または」です。絞りたいときは &。

次回

「どのプリムか」を書けるようになったので、次はプリムを外から持ってくる回です。 リファレンスとサブレイヤーの違い、そしてバリアント（同じアセットの色違い・LOD 違いを1つに束ねる仕組み）を扱います。 アセットを組み合わせて1つのシーンにする、という Solaris の本領のところです。
