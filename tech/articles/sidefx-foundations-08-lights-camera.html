Houdini 22 入門 8 — 1つのネットワークに2ショット置いてレンダリングする

houdini / 2026-08-24

出典: H22 Foundations | Model Render Animate 8 | Lights, Camera, Action! （SideFX 公式チュートリアル H22 Foundations: Model, Render, Animate の第8回・最終回 / Houdini 22 / 10:26 / 英語）。 このページは、上記の動画を見ながら自分用にまとめた日本語の学習メモです。SideFX 公式の翻訳ではありません。 前回はバウンシングボールをアニメートするでした。

この回で扱うこと

  • 1つの Solaris ネットワークに2つのショットを共存させる組み方
  • 書き出した USD を Reference で読み込むこと
  • この回いちばんの勘所 — プリム名を揃えるだけでマテリアルが当たる
  • 要らない静止ボールを Prune で消すこと。その前に「どう選ぶか」
  • 同じ camera1 を、ショットごとに編集して使い分けること
  • ショット別のライティングを Light Mixer でもう1つ作ること
  • Karma XPU で120フレームを1プロセスでまとめてレンダリングすること

1. ショット1に名前を付けて区切る

Solaris デスクトップに戻ると、レッスン5までのシーンがそのまま残っています。

まずレッスン5で作ったボールの回転（Edit ノード）を外に出して、 Null ノードを置いて shot_1 と名付けます。 ここまでが静止画のショットです。バイパスすれば、あの回転が何をしていたか確認できます。

Null を置くだけですが、「ここでショット1は完成」という区切りが目に見えるのが大事です。 このあと同じネットワークにショット2を足していくので、区切りがないと混乱します。

2. 枝分かれさせてショット2を作る

ショット2は背景のところから枝分かれさせます。 Reference ノードを置いて、そこから下に伸ばします。

設定値
File Pattern前回書き出した soccerball_anim の USD
プリムパス/geo/ の下に置きます

読み込むと、ボールが2つになります。レッスン4で持ち込んだ静止したボールと、 いま読み込んだアニメーション付きのボールです。

3. プリム名を揃えるとマテリアルが当たる

読み込んだアニメーションのボールにはテクスチャが乗っていません。 マテリアルの割り当てはプリムのパスに対してされているので、名前が違えば当たらないわけです。

直し方はとても素直です。読み込むプリムの名前を soccerball_geo にします。 既定ではファイル名などから作られる名前が入っているので、そこを書き換えます。 するとその瞬間にテクスチャが乗ります。

理由は動画の言葉がそのまま分かりやすいです。 「soccerball_geo という名前のものが2つではなく1つになったから」。 レッスン5で soccerball_geo に対して割り当てたマテリアルが、 アニメーションのボールにもそのまま効くようになります。

USD で作業するときにプリムの名前がそのまま接続点になることがよく分かる場面だと思います。 レッスン4でオブジェクト名を box_object1 から soccerball_geo に直しておいたのが、ここまで効いてきます。

4. 静止したボールを消す

静止したボールはショット2には要らないので消します。 面白いのはその前に「どう選ぶか」を見せているところです。

  1. 何も選択していない状態で、選択の種類を leaf primitive にします
  2. これで目的のメッシュだけを掴めます
  3. Tab から Prune を置きます

Prune は「これは要らない」と宣言するノードです。 消したのは静止したほうだけで、アニメーションのボールは残ります。

アニメーションのボールのほうは構造が複雑なので、選択の種類を component に変えると まとまり全体を掴めます。選択の粒度を切り替えられると作業が速くなります。

5. 位置をずらして画面外から入れる

Tab から Transform を置いて、アニメーションのボールを手前に引き戻します。 これでボールが画面の外から入ってくるようになります。

どのくらい引くかはカメラを見ながら決めます。動画でも一度決めた後にもう少し引き直しています。

6. 同じカメラを、ショットごとに編集する

ここがこの回でいちばん面白い考え方です。Tab から Camera Edit を置きます。

置いた直後はどのカメラを扱うか分からないのでエラーが出ます。 camera1 をドラッグして入れると解決します。

そのうえでカメラをビューにロックして、レッスン4と同じ操作で画角を決めます。 ボールが入ってくる方向と抜けていく方向を見ながら、少し回して詰めます。

大事なのはこの一点です。

ショットカメラ
ショット1camera1（レッスン4で決めたまま）
ショット2camera1 を Camera Edit で編集したもの

カメラを増やしていません。同じ camera1 を、 枝ごとに違う内容に編集しているだけです。 ショット1の枝に戻れば元のカメラのまま、ショット2の枝ではこのショット用のカメラになります。

LOP がレイヤーを重ねる仕組みだからこうなります。 「編集はその枝の中だけに書かれる」ので、同じ名前のものをショットごとに違う状態で持てます。 カメラを camera1 camera2 camera3 と増やしていく作り方とは考え方が違います。

7. ショット別のライティング

ライティングもショット2用に作り直します。Karma XPU で見ながら、 もう1つ Light Mixer を置きます。

今回は light1 に Specular モードを使って、 ハイライトを出したい場所をクリックして決めています。ポイントライトも同様です。

調整値
主となる方向のライトIntensity を 600 まで上げます
もう一方200、さらに落として 100 くらい
ドームライトスライダーでさらに下げます

ここでもソロ表示が効きます。1灯ずつ寄与を見て、 「こちら側が強すぎる」「こちらは足りない」と判断していけます。

そしてアニメーションの複数の時点で確認します。 静止画なら1枚見れば済みますが、動くものは「入ってくるとき」「跳ねているとき」 「抜けるとき」で見え方が変わるので、何点か確認する必要があります。

8. 連番でレンダリングする

Tab から Karma を選ぶと3つのノードが置かれます。 真ん中のものは今回使いません。

Karma Render Settings

設定値
レンダラXPU
Image Output Filters組み込みのものから OptiX デノイザを選びます
出力パスrender/ball_anim.$F2
カメラcamera1

$F2 は2桁パディングのフレーム番号です。 これで ball_anim.01, ball_anim.02, … という連番になります。 レッスン1で出てきた変数の3つ目が、最後にここで使われます。

ROP の設定

設定値
ノード名shot_2
フレーム範囲Render Specific Frame Range で 1 〜 120
プロセスRender All Frames With A Single Process

最後の項目が効きます。既定だと1フレームごとにプロセスを立ち上げ直すので、 起動のコストが120回かかります。まとめて1プロセスで回すほうが速く終わります。 シーンの読み込みが1回で済むぶんの差です。

hip を保存してから Render to Disk します。 終わったら Render > Play > Load Disk Files で連番を読み込んで確認できます。

この回のまとめ

  • 1つの Solaris ネットワークに複数のショットを置けます。枝分かれさせて、Null で区切りを付けます
  • 読み込んだプリムの名前を soccerball_geo に揃えるだけでマテリアルが当たります。USD では名前が接続点です
  • 要らないものは Prune で消します。その前に leaf primitive / component と選択の粒度を切り替えます
  • カメラを増やさず、同じ camera1 を Camera Edit でショットごとに編集します。枝の中だけに編集が書かれるからできることです
  • ライティングもショットごとに Light Mixer を置けます。動くものは複数の時点で確認します
  • $F2 で2桁パディングの連番になります
  • Render All Frames With A Single Process にすると、フレームごとの起動コストがなくなって速く終わります

シリーズを通して

これで9本が終わりです。1時間半で、モデリング・UV・ルックデブ・リギング・アニメーション・ レンダリングを1つのショットとして通したことになります。

振り返ると、後の回で効いてくる仕込みが前の回に置かれているのがよくできているなと思います。
