RBD のノード — 割る・束ねる・繋ぐ・解く

houdini-nodes / 2026-08-19

出典: SideFX 公式ドキュメント Rigid Body Dynamics (Houdini 公式) / RBD Bullet Solver SOP / RBD Material Fracture SOP。 このページは上記を日本語で要約・再構成した学習メモです。ノード名とパラメータ名は Houdini 22.0.368 の同梱ヘルプと実機で照合しています。

この記事で扱うこと

  • RBD も 3本の線（Geometry / Constraint / Proxy）を持ち回ること
  • 割る・パックする・拘束を作る・解く・仕上げを1ノードずつ
  • パックし忘れると重力でも落ちない話と、その見分け方

RBD も「3本の線」

FLIP と同じで、RBD のノードも複数の線を持ち回ります。

線中身
Geometry割れた破片そのもの
Constraint破片どうしを繋ぐ拘束（線のジオメトリ）
Proxy衝突判定用の簡略形状

rbdmaterialfracture / rbdconstraintsfromrules / rbdconstraintproperties はどれもこの3本を入出力に持ちます。 rbdbulletsolver の入力は Geometry / Constraint / Proxy / Collision / Guide Sim の5本です。

いちばん多い落とし穴 — パックし忘れ

rbdmaterialfracture の出力は「生のポリゴン」です。 ソルバの Geometry 入力はパックされた破片を期待しているので、 間に assemble を挟まないとソルバが何も掴めません。

症状は分かりにくくて、エラーが出ないまま、重力をかけても落ちないという形になります。 球の軌道・拘束の強度・サブステップを疑う前に、まず assemble があるか見てください。 実例の .hip に assemble が大量に入っているのはこれが理由です。

1. 割る

割り方が何種類もあるのは、材質によって割れ目の入り方が違うからです。

RBD Material Fracture rbdmaterialfracture

やること材質を選んで、それらしい割れ方で割る。拘束も一緒に作る
使いどころコンクリート・ガラス・木を壊すとき。まずこれを試す
入力1〜4
要のパラメータmaterialtype — 材質。これを変えると下のパラメータ一式が入れ替わる（既定 0）
concrete_detailsize — コンクリートの破片の大きさ（既定 0.05）
concrete_enablechipping — 縁の欠けを作る（既定 False）
glass_cornerratio — ガラスの角の割れ方（既定 0.5）
wood_cutdirvector — 木目の方向（既定 0.0 1.0 0.0）
randomseed — 乱数の種（既定 0）
注意パラメータ名は材質ごとに接頭辞が付きます（concrete_ / glass_ / wood_）。同じ「破片の大きさ」でも材質を変えると別のパラメータになります。

Voronoi Fracture voronoifracture

やること点を種にしてボロノイ分割で割る
使いどころいちばん基本の割り方。点の分布がそのまま破片の分布になる

割り方を細かく制御したいなら、種の点を自分で作って渡すのが基本です。

2. パックする（ここを飛ばすと落ちない）

ソルバはパックされた破片しか扱えません。

Assemble assemble

やること割れた結果を破片ごとにまとめ、名前を付けてパックする
使いどころ割った直後に必ず。RBD の必須ノード
入力1
要のパラメータpack_geo — パックする。これが本命（既定 False）
newname — 名前を新しく振り直す（既定 True）
createpackedfragments — パックドフラグメントとして作る（既定 True）
pieceattrib — 破片の名前を入れる属性（既定 __fracture_class__）
viewportlod — ビューポートでの表示のしかた（既定 0）
注意newname（既定 ON）は glue 拘束を壊します。rbdmaterialfracture が付ける名前は piece0-0-1 のような階層式なのに、piece0.. に付け替えられて拘束の参照名が全部切れます。強度を -1 にしても 0 にしても同じ壊れ方になり、エラーは出ません。newname=0 + pack_geo=1 で使ってください（実測）。

3. 拘束を作る（どこが繋がっているか）

拘束は線のジオメトリです。点が破片の重心、線が「繋がっている」という意味になります。

RBD Constraints From Rules rbdconstraintsfromrules

やることルールを書いて拘束を自動で張る
使いどころ接している破片どうしを繋ぐ、いちばん普通のやり方
入力1〜4
要のパラメータconnectiontype — 繋ぎ方（既定 2）
group — 対象の破片（既定 0）
groupname — できた拘束のグループ名（既定 connectors）

公式リファレンス（英語）

RBD Constraint Properties rbdconstraintproperties::2.0

やること拘束の強さ・種類・壊れ方を決める
使いどころ「ここだけ弱くする」を作る段。破壊の演出はほぼここ
入力0〜3
要のパラメータconstrainttype — 拘束の種類（glue / hard / soft など）（既定 0）
doglue_strength — glue の強度を有効にする（既定 False）
constraintgroup — 対象の拘束グループ
constraintname — 拘束の名前（既定 Glue）
clusterattrib — クラスタの属性名（既定 parentpiece）
注意doglue_strength を入れないと強度は効きません。値だけ入れても素通りします。数珠つなぎにしてグループを絞りながら上書きしていくのが定石です。

公式リファレンス（英語）

Glue Cluster gluecluster

やることクラスタの値に応じて glue 拘束の強度を付ける
使いどころ塊の内側は硬く、塊どうしは弱く、を作るとき
入力1
要のパラメータintracluster — 塊の内側の強度（既定 -1）
intercluster — 塊どうしの強度（既定 1）

注意このノードは強度を「置き換え」ます。材質ごとに強度を積み上げてきた設定とは両立しません。実測では、材質別に 40.0 と 3.0 を振り分けた拘束が全部これで上書きされていました。併用するなら順番に注意してください。

詰まりやすいところ

症状まず見るところ
重力をかけても落ちない assemble でパックしているか。 生ポリゴンのままだとソルバが掴めない
強度をいくつにしても同じ壊れ方 assemble の newname が ON で、 拘束の参照名が切れている
強度が効かない rbdconstraintproperties の doglue_strength
材質ごとの強度が全部同じになる gluecluster が後から上書きしていないか
破片が貫通する サブステップ、次に bullet_collision_margin
そもそも割れているのか分からない rbdexplodedview で開いて見る
移動したら拘束が置いていかれた xform ではなく rbdxform
