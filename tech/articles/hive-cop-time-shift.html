Adjacency でエフェクトを UV シームを越えて伝播させる

houdini-cop / 2026-08-24

出典: H22 - Copernicus and Time Shift | Jakub Spacek | Houdini 22 HIVE （SideFX 公式 Houdini 22 HIVE の講演 / 講演者 Jakub Spacek さん / Houdini 22 / 24:08 / 英語）。 このページは、上記の動画を見ながら自分用にまとめた日本語の学習メモです。SideFX 公式の翻訳ではありません。

主題

adjacency ノードを使って、エフェクトを UV 空間上で「広がらせる」話です。

要点はUV シームで途切れないこと。 テクスチャ空間で何かを伝播させると、通常はアイランドの境目で止まってしまいます。 adjacency はメッシュの隣接関係を持っているので、シームを越えて繋がります。

1. 前提 — UV アイランドを均しておく

UV Layout の Spread Islands to All Available Space を有効にします。

adjacency ノードを使う前提として重要です。 アイランドが偏っていると、広がる速度が場所によって変わってしまいます。 UV 空間を均等に使わせておくことで、伝播の速さが揃います。

2. 先端を作る — H22 で機能が入った

エフェクトの先端（leading edge）を作る話です。

正直な話が入っていて、講演者は当初は自分でソルバを組んで時間経過の散逸を実装していたそうです。 ところが H22 に同じことをする機能が入りました。

自作していたものが標準機能になる、というのは追いかけている側にはよくある話ですが、 それをそのまま話しているのが良いなと思いました。

3. UV シームで問題が出ない

これがこの講演の中心的な成果です。シームでの問題が一切出ません。

色も同じ原理で作っていて、hue shift と saturation をオフセットするやり方です。 伝播している位置に応じて色相と彩度をずらせば、先端と後方で違う色になります。

加えて Ripple Solver を試用していて、 SOP でやっていたことが Copernicus でできることを確認しています。

4. うまくいかなかった話

各アイランドの上に機械学習のパターンを育てる構想があったそうですが、 時間がかかりすぎることを見誤ったと正直に述べています。

講演で「やろうとしたができなかった」を話す人は少ないので、 このあたりは読む価値があると思います。

5. トポロジが前提になる

実務上いちばん気をつけるべき点がここです。

三角形分割で密で汚い領域があると、UV アンラップがクラッシュするまで cook し続けた。

トポロジを整えることが前提です。 adjacency は隣接関係に依存するので、メッシュが荒れていると成立しません。

「この手法を使いたいならモデルの側から整える必要がある」という制約なので、 導入を考えるときは先に確認しておいたほうがよさそうです。

この講演から持ち帰るもの

  • adjacency ノードは UV シームを越えて伝播します。これが機能の核です
  • 前提として UV Layout の Spread Islands to All Available Space でアイランドを均しておきます
  • 先端（leading edge）の散逸はH22 で標準機能として入りました（講演者は自作していたそうです）
  • 色は hue shift と saturation のオフセットで作れます
  • Ripple Solver で SOP でやっていたことが Copernicus でできます
  • トポロジが荒れていると UV アンラップがクラッシュします。整えるのが前提条件です
