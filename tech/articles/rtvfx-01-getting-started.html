リアルタイムVFXの学び始め — Real Time VFX の定番スレッドから

realtime-vfx / 2026-08-19

この記事は Real Time VFX（リアルタイムVFXアーティストのコミュニティフォーラム）で 定番とされているスレッドを読んで、学び始めの道筋としてまとめたものです。 解説は自分の言葉で書き、各項目に出典スレッドへのリンクを付けています。 各スレッドの画像や動画は投稿者本人の著作物なので転載していません。中身はリンク先でご覧ください。

この記事の位置づけ

リアルタイムVFXを学び始めようとすると、情報が散らばっていてどこから手を付けるか迷います。 Real Time VFX には10年分の蓄積があり、定番と呼ばれるスレッドがいくつかあります。 それを「何を、どの順番で読むか」という地図にしたのがこの記事です。

先に重要な注意点をひとつ。 定番スレッドの多くは 2016〜2020年のものです。 考え方や原則は今も有効ですが、ツールやエンジンの記述は古くなっています。 具体的には記事の最後にまとめました。

1. そもそも何をする仕事か

映像のVFXと違い、リアルタイムVFXはゲームエンジンの中で、実際に動いている最中に計算されるエフェクトを作ります。 そのため制約が違い、優先されるものも違います。

この違いをよく表しているのが、Riot Games で League of Legends のVFXを担当していた ShannonBerke さんの言葉です。自身のデモリールを紹介するスレッドの中で、こう書いています。

League ではゲームプレイが王様なので、派手すぎたりコントラストが強すぎたりするものは何もありません。

きれいなエフェクトを作ることと、ゲームとして成立させることは別という前提が、 最初に押さえておくべきところだと思います。プレイヤーが状況を読み取れなくなるエフェクトは、 どれだけ美しくても採用されません。

出典: Shannon McSheehan - LoL FX + Knowledge Share （ShannonBerke さん / 2016-11）。このサイトで最も反応が多いスレッドで、 332件の投稿が付いています。作例の GIF コレクションが集められていて、 「どう作ったか質問があれば答えます」と書かれているのも参考になります。

エンジンはどちらを選ぶか

よくある質問への回答として、大意こう書かれています。

  • Unreal — アーティストにとって扱いやすく、標準機能だけでできることが多い。 ただし機能が多くエンジンが巨大なので、圧倒されることがある
  • Unity — やや技術寄り。自分でシェーダーを書いたり構成を組んだりする自由度が高い

ただし「違いは小さいので、好きなほうでよい」という結論でした。

出典: Getting Started in Real Time VFX? Start Here! （Travis さん / 2018-04）

3. まず理解すべき2つの基本テクニック

Augie さんが「新しく入ってくる人が多いので、日常的に使う基本を書く」として 2つのチュートリアルを投稿しています。この2つは、多くのエフェクトの土台になります。

スクロールするテクスチャ＋マスク

ノイズテクスチャを流し、その上からマスクで形を切り抜く手法です。 投稿者本人が「Diablo 3 のプレゼンで出てきたあの手法」と呼んでいます。

炎、煙、魔法陣、オーラ——見た目がまったく違うものが、 実は同じ「流す＋抜く」の組み合わせでできていることが分かります。 最初にこれを理解しておくと、他人のエフェクトを見たときに構造が読めるようになります。

出典: VFX Basics - Creating the scrolling texture with mask setup （Augie さん / 2017-03）

メッシュに沿ってテクスチャを流す

Augie さんが Soulercoaster と呼んでいる手法です。 「ジェットコースターみたいなものだから」という命名だそうです。

平坦な UV を持つメッシュを自作し、そこにテクスチャを流します。

パーティクルのトレイルのような見た目でありながら、 メッシュエフェクトの自由な複雑さを持てます。

用途として挙げられているのは、武器の斬撃、鬼火のようなトレイル、魔法陣のディテールです。 使う元のメッシュは「引き伸ばしたポリゴン平面」で構いませんが、 UV が平坦でまっすぐなことと、上端が UV の上端に揃っていることが条件です。 横方向ではなく、メッシュに沿って流したいためです。

出典: VFX Basics - Mesh Soulercoasters （Augie さん / 2017-03）

4. 技術ではなく原則を学ぶ

手法を覚えると作れるようにはなりますが、良し悪しの判断はできません。 そこを扱っているのが Keyserito さんの投稿です。

League of Legends を題材にした5本の動画シリーズで、 リアルタイムVFXの造形的な原則を扱っています。 GDC での講演をもとに、League of Legends のスタイルガイドから得た知見を加えたもの、と説明されています。

スレッドに付いたコメントが、この分野の性質をよく表していました。

これこそが大事なところです。私たちはこういうことを忘れて、技術的な細部にばかり注目してしまいます。

エンジンに依存しない話なので、ここは今読んでも古びていません。 むしろ最初に見ておくと、手法を学ぶときの軸ができると思います。

出典: Artistic Principles of VFX （Keyserito さん / 2018-02）

5. 実際の仕事は何をするのか

これは学習段階では見えにくい部分で、個人的にいちばん参考になったスレッドです。

Travis さんが、新人VFXアーティストとして入社してから何をしていたかを具体的に書いています。 大学を出たばかりで、実務経験はポートフォリオの個人制作のみ、という状態からのスタートでした。

最初にやることは地味

  • 環境用のループするアンビエントエフェクトや、ヒット時の小さなエフェクトを大量に作る
  • すでにゲーム内にあるテクスチャやフリップブックを再利用する
  • デザイナーが用意した仕掛けに対して、どこから再生されるか・何秒必要か・どんな見た目かを聞いて作る

プレースホルダーの作り方が実務的

新人が多くやることとして挙げられていたのが、仮のエフェクト作りです。ただし作り方に工夫があります。

素早く、機能する（ループして呼び出しで止められるなど）エフェクトを作ります。 このとき最終的な命名規則を付けておき、Blueprint やアニメーションの呼び出しに紐づけ、 向きとサイズを正しく合わせておきます。

こうしておけば、あとから自分や先輩が テクスチャとマテリアルを差し替えるだけで完成品にできるという考え方です。 仮のものを作るときに、後工程を楽にする形で作っておく。ここは覚えておきたいところでした。

フォルダとエフェクトの整理も仕事のうち、と明記されているのも実態が伝わってきます。

出典: Beginning VFX Artist - Advice for beginners, from a beginner （Travis さん / 2017-09）
