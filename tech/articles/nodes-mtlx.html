MaterialX のノード — 型が厳密なシェーダー

houdini-nodes / 2026-08-19

出典: SideFX 公式ドキュメント MaterialX (Houdini 公式) / MaterialX nodes / Karma materials。 このページは上記を日本語で要約・再構成した学習メモです。ノード名とパラメータ名は Houdini 22.0.368 の同梱ヘルプと実機で照合しています。

この記事で扱うこと

  • MaterialX が型に厳密であること、signature で型が変わる仕組み
  • サーフェス・BSDF・テクスチャ・座標・ノイズ・色・数学・合成を1ノードずつ
  • 結線が黙って外れる落とし穴（実測）

MaterialX は型に厳密

Blender のシェーダーノードは、色を Shader ソケットに挿しても何となく動きます。 MaterialX はそれを許しません。 color3 と vector3 と float は別の型で、 繋がらないものは繋がりません。

そのぶん、同じ計算に型ごとの別ノードが必要になりそうですが、そうはなっていません。 1つのノードが signature というパラメータで型を切り替えます。
mtlxadd の signature = float float 同士を足す
mtlxadd の signature = color3 色同士を足す
mtlxadd の signature = vector3 ベクトル同士を足す
スクリプトで組むときの実測メモ
signature は結線したあとに設定する メニューの中身が繋がった入力の型で絞り込まれるため、繋ぐ前だと目的の値が選べません
signature を変えると線が黙って外れる 型が合わなくなった結線が、警告もエラーも無く切れます。 「結線 → signature」を変化が無くなるまで交互に回してから、最後にもう一度繋ぎ直すのが確実です
素の型のトークンは "default" "float" ではありません
トークンにアンダースコアは入らない color3vector3 であって color3_vector3 ではない。 間違えると黙ってメニューの先頭に落ちます

この「エラーが出ないまま線が外れる」が MaterialX でいちばん厄介なところです。 出来上がったマテリアルが真っ黒／真っ白になったら、まず出口までの線が生きているかを疑ってください。

Houdini 独自のノード

名前に h が入るもの（hmtlxrampc のように先頭に付くものと、 mtlxhuniformramp のように mtlx の後に付くものがあります）は Houdini が独自に足したもので、MaterialX の標準にはありません。 ランプなど、標準では表現しにくいものが入っています。 他のアプリに持っていくときは互換性に注意してください。

9. 型の変換・分解・合成

詰まりやすいところ

症状まず見るところ
マテリアルが真っ黒／既定の灰色 出口までの線が切れていないか。 signature を変えたときに黙って外れます
色を繋いだのに真っ黒（OpenPBR） base_weight が 0 になっていないか
テクスチャの模様が出ない／全面単色 mtlxplace2d の scale。 掛けるのではなく割ります
ノイズが動かない 座標の入力は in ではなく position
ランプのカーブの後半が消える キーが 10 個を超えている
Solaris で /materials に何も出ない マテリアルフラグが立っていない。 materiallibrary LOP はフラグの立った子だけを拾います
法線の陰影が明後日の方向 mtlxnormalmap の空間（接空間／ワールド）

スクリプトで組むときの順番

Blender からの変換器を書いたときに、この順番でないと通りませんでした。

  1. ノードを作る（パラメータはまだ書かない）
  2. 「結線 → signature」を、変化が無くなるまで交互に回す
  3. signature 以外のパラメータを書く
  4. もう一度結線する（型の変更で外れた線を戻す）
  5. 線が本当に生きているか検証する

4 と 5 を省くと、ビルドは成功したのに絵が出ないという状態になります。
