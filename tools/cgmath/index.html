    CHAPTERはじめに：数式なしで読むためのルール

    CGの数学は、突き詰めると「点を動かす」「向きを測る」「大きさを変える」の3つでほぼ全部です。この教材では、数学の記号を一切使わず、全部プログラムの書き方で説明します。

    この教材の書き方ルール

    • ベクトル（矢印）は {x: 2, y: 1} のような「値のセット」。中身は v.x のように取り出します。
    • 掛け算は *、割り算は /、平方根は sqrt()、円周率は PI（= 3.14159...）。
    • 数学の「関数」は、本当にプログラムの関数です。dot(a, b) と書いてあったら「a と b を渡すと、数字が1個返ってくる」という意味。
    • 「数学ではこう書く」は折りたたみに隠してあります。他の資料を読むとき用なので、最初は開かなくてOK。
    // この教材で出てくるコードは、だいたいこの形です
const v = { x: 2, y: 1 };          // 「右に2、上に1」の矢印

function length(v) {               // 矢印の長さを返す関数
  return Math.sqrt(v.x * v.x + v.y * v.y);
}

    CHAPTERベクトル：数字のセットを「矢印」として考える

    ベクトルとは、数字を何個かまとめたものです。CGでは 「矢印」 だと思うと一気にラクになります。

    const v = { x: 2, y: 1 };   // 右に 2、上に 1 進む矢印
const p = { x: 3, y: 0, z: -5 };  // 3D なら z が増えるだけ

    同じ {x: 2, y: 1} でも、読み方が2つあります。

    • 位置として読む：「原点から矢印の先端の場所」。キャラクターの座標など。
    • 移動として読む：「どっちにどれだけ動くか」。速度、風、ジャンプの勢いなど。

    足し算＝矢印をつなげる

    青い矢印 a の先端と、黄色い矢印 b の先端をドラッグしてみてください。

    function add(a, b) {
  return { x: a.x + b.x, y: a.y + b.y };   // 中身をそれぞれ足すだけ
}

    「a だけ進んで、そこから b だけ進む」と「a + b を一気に進む」は同じ場所に着く。これが足し算の意味の全部です。

    数字を掛ける＝矢印を伸び縮みさせる

    function scale(v, k) {
  return { x: v.x * k, y: v.y * k };
}
scale(v, 2);     // 2倍の長さ（向きは同じ）
scale(v, 0.5);   // 半分
scale(v, -1);    // 真逆の向き

    スライダーで k を変えると、矢印がどう変わるか見てください。

    CHAPTER長さと正規化：「向きだけ」を取り出す

    矢印の長さの求め方と、長さを 1 に揃える normalize（正規化）。CGのコードで一番よく見る関数のひとつです。

    長さ＝三角形の斜めの辺

    矢印の先端をドラッグ。横の長さ v.x と縦の長さ v.y から、斜めの長さが決まります。

    function length(v) {
  return Math.sqrt(v.x * v.x + v.y * v.y);   // 3D なら + v.z * v.z を足すだけ
}

    なぜ「二乗して足して sqrt」なのか。図の直角三角形で、横の二乗 + 縦の二乗 = 斜めの二乗 になるという昔からの事実（ピタゴラスの定理）があるからです。だから斜めの長さは、その平方根。理由まで覚えなくても、「length() は矢印の長さを返す」で十分です。

    normalize：長さを 1 にする

    function normalize(v) {
  const len = length(v);
  return { x: v.x / len, y: v.y / len };   // 自分の長さで割る → 長さが 1 になる
}

    上の図の 黄色い矢印 が normalize した結果です。元の矢印をどれだけ伸ばしても、黄色は円（半径1）の上から動きません。向きの情報だけが残る、ということです。

    なぜ長さ 1 が便利？
    「向き」を比べたいとき、長さが混ざっていると邪魔だからです。ライトの向き、カメラの向き、面の向き（法線）は、CGでは基本的に全部「長さ 1」で持ちます。次の章の内積が、これで劇的にシンプルになります。
    バグの定番：長さ 0 の矢印
    {x: 0, y: 0} を normalize すると 0 で割ることになり、結果が NaN（数字じゃない）になります。実際のコードでは「長さが 0 ならそのまま返す」などのガードを入れます。
    数学ではこう書く（読まなくてOK）

    長さは |v| や ‖v‖ と書きます。normalize した結果は v の上に ^ を付けて「vハット」と読みます。

    normalize({x: 3, y: 4}) の結果は？

    CHAPTER内積（dot）：2本の矢印は、どれくらい同じ向き？

    内積は、2本の矢印を渡すと 「どれくらい同じ方向を向いているか」を1つの数字 にして返す関数です。CGでもLLMでも、たぶん一番働いている関数。

    function dot(a, b) {
  return a.x * b.x + a.y * b.y;   // 3D なら + a.z * b.z
}

    2本の矢印の先端をドラッグ。角度が変わると dot の値がどう変わるか見てください。点線は「b を a の上に落とした影」です。

    読み方：長さ1どうしなら、-1 〜 1 の「同じ向き度」

    • 1：完全に同じ向き
    • 0：直角（関係なし）
    • -1：真逆
    • その間は、なめらかに変わります。実はこの値は cos(角度) と同じものです（第5章）。

    長さが 1 でない場合は「同じ向き度 × a の長さ × b の長さ」になります。だから CG では、向きを比べたいときは先に normalize してから dot します。

    使い道1：ライティング（面の明るさ）

    面の向き（法線 normal）と、ライトの向き lightDir が同じ方向を向いているほど明るい。これだけで、あの「球に光が当たっている感じ」が作れます。

    // 一番シンプルな陰影（ランバート反射）。ゲームも映画も、根っこはこれ
const brightness = Math.max(0, dot(normal, lightDir));
// max(0, ...) は「裏側（マイナス）は 0 にする」。真っ暗より暗くはならない

    ライトの向きを動かすと、球の各点で dot(normal, lightDir) が計算され直しています。球の表面すべての点で、同じ1行が走っているだけです。

    使い道2：「前にいる？後ろにいる？」の判定

    const toEnemy = normalize(sub(enemy.pos, player.pos));   // 敵への向き
if (dot(player.forward, toEnemy) > 0.7) {
  // 敵はだいたい正面（視野角 約90度）にいる
}

    視界判定、バックフェースカリング（裏向きの面を描かない）、影の長さ、反射の計算。全部これの応用です。

    CHAPTER外積（cross）：面の「向き」を作る

    内積が「同じ向き度」を返す関数なら、外積は 「2本の矢印の両方に直角な、新しい矢印」 を返す関数。3D の面の向き（法線）はこれで作ります。

    まず 2D で：右？左？そして面積

    function cross2d(a, b) {
  return a.x * b.y - a.y * b.x;   // 2D では数字が1つ返る
}

    2本の矢印をドラッグ。b が a の左にあるか右にあるかで、符号が変わります。

    • プラス：b は a の左側（反時計回り）
    • マイナス：b は a の右側（時計回り）
    • 0：平行（同じ直線上）
    • 値の大きさ＝2本の矢印が張る 平行四辺形の面積。三角形の面積はその半分。

    3D で：両方に直角な矢印＝法線

    function cross(a, b) {
  return {
    x: a.y * b.z - a.z * b.y,
    y: a.z * b.x - a.x * b.z,
    z: a.x * b.y - a.y * b.x,   // ← 2D 版と同じ形が z に入っている
  };
}

// 三角形 A, B, C の法線（面の向き）
const normal = normalize( cross( sub(B, A), sub(C, A) ) );

    「A から B への辺」と「A から C への辺」は、どちらも三角形の面の上に乗っている矢印。その両方に直角ということは、面から垂直に生えている矢印 です。それが法線。

    三角形が回転しています。緑の矢印が cross() で作った法線。面の明るさは第3章の dot(normal, 視線) で決めていて、裏を向くと赤くなります。

    内積と外積はセットで働く
    外積で 面の向き を作り、内積で その向きとライトの同じ向き度 を測る。これがライティングの骨格です。「裏向きの面は描かない（バックフェースカリング）」も、dot(normal, カメラへの向き) < 0 なら裏、という1行です。

    順番に注意：cross(a, b) と cross(b, a) は真逆の矢印になります。3Dツールで「法線が反転してる」「面が裏返ってる」と言われるのは、頂点の順番が逆だったということです。

    外積は a×b と書きます。「クロス積」とも。「ベクトル積」と書く本もあります。

    CHAPTERsin / cos：「角度」から「矢印」を作る道具

    三角関数と聞くと身構えますが、CGで必要なのは1つだけ。「角度 angle を渡すと、その向きの長さ1の矢印が返ってくる」。それが sin と cos です。

    // 角度 angle の方向を向いた、長さ 1 の矢印
const dir = { x: Math.cos(angle), y: Math.sin(angle) };

    スライダーで角度を変えると、円の上の点が動きます。その点の x が cos、y が sin。右のグラフは、角度を増やしていったときの x と y の変化です。

    ラジアン：プログラムの角度の単位

    Math.cos() に渡す角度は「度」ではなく「ラジアン」です。難しく考えなくて大丈夫。一周 360° = 2 * PI、それだけ。

    const rad = deg * Math.PI / 180;   // 度 → ラジアン
//  90° = PI / 2      180° = PI      360° = 2 * PI

    回転：点をぐるっと回す

    function rotate(p, angle) {
  const c = Math.cos(angle);
  const s = Math.sin(angle);
  return {
    x: p.x * c - p.y * s,
    y: p.x * s + p.y * c,
  };
}

    この式の形、次の章の「行列」でもう一度出てきます。実は rotate は「行列で変換する」の一例です。

    波：時間を角度に入れると揺れる

    CHAPTER行列：空間ぜんぶを変形する「レシピ」

    行列は数字の表に見えますが、正体はシンプル。「x 方向の矢印 i がどこへ行くか」「y 方向の矢印 j がどこへ行くか」を書いたメモ です。それだけで空間全体の変形が決まります。

    // 行列 = 「i の行き先」と「j の行き先」のセット
const m = {
  i: { x: 1, y: 0 },   // 右向きの矢印 {1,0} は、変形後どこへ？
  j: { x: 0, y: 1 },   // 上向きの矢印 {0,1} は、変形後どこへ？
};                       // ↑これは「何もしない」行列（単位行列）

function transform(m, p) {
  // p = 「i を p.x 個 と j を p.y 個」 なので、行き先も同じ組み合わせ
  return add( scale(m.i, p.x), scale(m.j, p.y) );
}

    緑の矢印 i と ピンクの矢印 j の先端をドラッグ。方眼ごと家が変形します。紫の点は「変形前の点 p」で、変形後の行き先が表示されます。

    「回転」も「拡大」も、行列の中身が違うだけ

    // 回転 45°： i と j をどちらも 45° 回した先を書く（第5章の rotate と同じ式）
{ i: { x: cos(a), y: sin(a) },  j: { x: -sin(a), y: cos(a) } }

// 拡大： i を 2 倍、j を 0.5 倍
{ i: { x: 2, y: 0 },  j: { x: 0, y: 0.5 } }

// せん断（斜めにずらす）： j だけ右に傾ける
{ i: { x: 1, y: 0 },  j: { x: 1, y: 1 } }

    行列の掛け算＝変形を続けて行うこと

    「回転してから拡大」と「拡大してから回転」は、上のボタンで試すと分かるように 結果が違います。行列どうしを掛けるとは「2つの変形をまとめて1つの行列にする」ことで、順番が大事です。

    // 「先に a、次に b」をまとめた行列。i と j を a で変形して、さらに b で変形した先を書く
function compose(b, a) {
  return {
    i: transform(b, a.i),
    j: transform(b, a.j),
  };
}
    つながり：面積が何倍になるか ＝ cross2d(m.i, m.j)
    第4章の外積は「2本の矢印が張る平行四辺形の面積」でした。i と j は元々 1×1 の正方形を張っているので、変形後の cross2d(m.i, m.j) は「面積が何倍になったか」。これを 行列式（det） と呼びます。マイナスなら裏返っている、0 なら潰れている。上の図の readout に出ています。

    行列は数字を縦横に並べて [[a, c], [b, d]] のように書きます。左の列が i の行き先、右の列が j の行き先です。点 p の変形は M·p と書きます。掛け算 AB は「先に B、次に A」の意味なので、右から読みます。

    CHAPTER3D と投影：立体が画面に映るまでの道のり

    3D は「z が増えるだけ」。行列も i, j に k が増えるだけ。でも1つだけ困ることがあって、それを解決するのが 4×4 行列 です。そして最後に「遠いものは小さく」するのが投影。

    困りごと：行列は「原点」を動かせない

    行列は i, j, k の行き先を書いたメモでした。すると原点 {0,0,0} は、何を掛けても {0,0,0} のまま。つまり 平行移動（ずらす）が書けない。回転と拡大はできるのに、移動だけできないのは不便です。

    解決策：座標に w: 1 という4つ目の値を付け足し、行列にも「w 方向の矢印 t の行き先」を足す。すると p.w = 1 なので、t が「原点がどこへ行くか」＝平行移動になります。

    const p = { x: 1, y: 2, z: 3, w: 1 };   // w は「1」を入れておくだけの席

const m = {
  i: {...}, j: {...}, k: {...},     // 回転・拡大（3×3 と同じ）
  t: { x: 5, y: 0, z: 0 },        // ← 平行移動：右に 5 ずらす
};

function transform4(m, p) {
  return add( scale(m.i, p.x), scale(m.j, p.y), scale(m.k, p.z), scale(m.t, p.w) );
}                                  // p.w = 1 なので t がそのまま足される

    これが「4×4 行列」「同次座標」の正体です。難しい名前ですが、やっていることは「移動も行列に入れたいから席を1つ増やした」だけ。

    パイプライン：3つの座標変換

    スライダーを動かすと、立方体の頂点が「モデル → ワールド → カメラ → 画面」と変換されて描かれます。readout は頂点1つ分の途中経過です。

    1. モデル → ワールド：物を世界に置く。回転・拡大・移動の行列を掛ける。
    2. ワールド → ビュー（カメラ）：カメラが原点に来るように、世界ぜんぶを逆にずらす。「カメラを動かす」＝「世界を逆に動かす」。
    3. 投影：遠いものを小さくして、2D に潰す。

    投影の正体：z で割るだけ

    function project(p, focal) {
  return {
    x: p.x / p.z * focal,   // 遠い（z が大きい）ほど、画面の中心に寄る＝小さく見える
    y: p.y / p.z * focal,
  };
}

    遠近感の全部が / p.z の1文字です。focal（焦点距離）はズームの強さ。「視野角（FOV）」は同じものを角度で言い換えただけで、視野が広い＝focal が短い、です。平行投影にすると割り算をしないので、遠くても同じ大きさになります。

    なぜここまで全部「行列」なのか
    モデル・ビュー・投影の3つを compose() で1つの行列にまとめれば、頂点ひとつにつき掛け算1回で済みます。GPU は「行列 × ベクトル」を何百万回も同時にやる機械。だから CG は行列で書くのです。

    頂点 v の変換は P·V·M·v と書きます（右から順に、Model → View → Projection）。MVP 行列という言葉はこれです。

    CHAPTER補間（lerp）：A と B の「あいだ」を作る

    アニメーション、グラデーション、ブレンド、テクスチャの色の混ぜ合わせ。全部この 3行の関数 から始まります。

    function lerp(a, b, t) {
  return a + (b - a) * t;   // t=0 で a、t=1 で b、t=0.5 でちょうど真ん中
}

    t を動かすと、点の位置・色・グラフの3つが同時に変わります。イージングを切り替えると「t の変え方」が変わります。

    ベクトルにも色にも、そのまま使える

}
// 色も同じ（r, g, b をそれぞれ lerp）。グラデーションの正体
const color = lerpVec3(red, blue, t);

    イージング：t を「変形」してから lerp する

    t を 0 → 1 に一定の速さで動かすと、機械的な動きになります。t 自体を曲げてから lerp に渡す と、「最初ゆっくり、最後ゆっくり」のような自然な動きになります。

function easeOut(t)    { return 1 - (1 - t) * (1 - t); }   // 最初速く、最後ゆっくり

  return x - Math.floor(x);                                // 小数部分だけ取る → 0〜1
}

    CHAPTERノイズ：乱数を「なめらか」にすると、地形と雲になる

    rand は隣どうしが無関係にバラバラ。それを 格子の上だけ乱数にして、間を lerp でつなぐ と「なめらかなバラバラ」= ノイズになります。Mountain SOP、Attribute Noise、雲・地形・木目、ほぼ全部これ。

    周波数（細かさ）と重ねる回数を変えてみてください。「重ねる」= 細かいノイズを小さく足していく。これを fBm（フラクタルノイズ）と呼びます。

    // 1. 格子点 (整数の場所) だけ rand で決める。2. 間は第8章の lerp でつなぐ
function noise(x, y) {
  const ix = Math.floor(x), iy = Math.floor(y);      // どの格子マスにいるか
  const fx = x - ix,        fy = y - iy;             // マスの中のどこか (0〜1)
  const sx = smoothstep(fx), sy = smoothstep(fy);   // 角ばらないように曲げる
  const a = rand2(ix, iy),     b = rand2(ix + 1, iy);
  const c = rand2(ix, iy + 1), d = rand2(ix + 1, iy + 1);
  return lerp( lerp(a, b, sx), lerp(c, d, sx), sy );   // 4隅を混ぜる
}

// 3. 細かいノイズを、だんだん小さく重ねる (fBm)
function fbm(x, y, octaves) {
  let sum = 0, amp = 0.5, freq = 1;
  for (let i = 0; i < octaves; i++) {
    sum  += noise(x * freq, y * freq) * amp;
    freq *= 2;     // 2倍細かく
    amp  *= 0.5;   // 半分の強さで
  }
  return sum;
}
    パラメータの読み方（Houdini のノイズ系ノード共通）
    • Frequency / Element Size：細かさ。座標に掛ける数。
    • Amplitude：強さ。結果に掛ける数。
    • Octaves / Turbulence：重ねる回数。多いほどザラザラした細部が増える。
    • Roughness：重ねるときに amp を何倍にするか（上のコードでは 0.5）。
    • Offset：座標に足す数。time を足すと流れる。
    Houdini でやるなら

    CHAPTER距離関数（SDF）：形を「そこまでの距離」で表す

    「円」を 「中心からの距離 − 半径」を返す関数 で表す。これが距離関数（SDF）。マイナスなら中、プラスなら外、0 なら輪郭。Houdini の VDB、Boolean、Distance from Geometry の裏側はこれです。

  return length( sub(p, center) ) - r;
}

// 四角の距離関数（少しトリッキーだけど、やってることは「中心からの距離」）
function sdBox(p, center, half) {
  const d = { x: Math.abs(p.x - center.x) - half.x, y: Math.abs(p.y - center.y) - half.y };
  return length({ x: Math.max(d.x, 0), y: Math.max(d.y, 0) }) + Math.min(Math.max(d.x, d.y), 0);
}

function falloff(p, center, r, soft) {

// smoothstep の「範囲付き」版。lo 以下で 0、hi 以上で 1、間はなめらか

  return t * t * (3 - 2 * t);

    CHAPTER波の重ね合わせ：足すだけで、干渉と波紋になる

    第5章の sin は「1本の波」でした。波は足せる。2つの波源からの sin を足すと干渉縞、たくさん足すと海面。Ripple Solver や Ocean Spectrum の一番奥にあるのは、この足し算です。

    2つの波源（点）をドラッグ。各点の高さ = sin(波源1までの距離 × f − time) + sin(波源2までの距離 × f − time)。重なって強め合う所と打ち消し合う所ができます。

    // 点 p の高さ。波源が何個あっても「距離で sin を作って足す」だけ
function height(p, sources, freq, time) {
  let h = 0;
  for (const s of sources) {
    const d = length( sub(p, s) );          // 波源までの距離
    h += Math.sin(d * freq - time);           // 距離が進むほど位相が進む → 同心円の波
  }
  return h;                                   // 波源が 2 個なら -2〜2
}

    足すと何が起きるか

    • 山と山 が重なる所は高く（強め合う）、山と谷 が重なる所は 0（打ち消す）。これが干渉。
    • 方向の違う平らな波（sin(dot(p, dir) * f)）を何本も足すと、それっぽい海面になる。Ocean Spectrum はこれを何百本も、周波数ごとの強さを変えて足しています。
    • 時間 time を引くと、波が外に進む。足すと内に進む。
    Houdini でやるなら

    CHAPTERL-system：「文字の置き換え」だけで植物が生える

    Houdini の L-System SOP は魔法に見えますが、中身は2段階。1. 文字列を「ルール」で置き換えて長くする。2. その文字列を「亀」に読ませて線を描く。 数学というより、文字遊びです。

    ステップ1：置き換えのルール

    // 出発の文字列（Premise）と、置き換えルール（Rule）
const axiom = "F";

function expand(text, rules, generations) {
  for (let g = 0; g < generations; g++) {
    let next = "";
    for (const ch of text) next += rules[ch] || ch;   // ルールがある文字は置き換え、無ければそのまま
    text = next;
  }
  return text;
}

  else if (ch === "-") turtle.angle -= delta;         // 右に曲がる

    L-system は「文字列」で自己相似を作りました。同じことを 「関数が自分自身を呼ぶ」 で書くのが再帰。木、雪の結晶、海岸線、山。「どこまで拡大しても同じ形」= フラクタルは、たいてい数行の再帰です。

    // 木を描く関数。「枝を1本描いて、その先で自分を2回呼ぶ」だけ
function tree(pos, angle, len, depth) {
  const end = add(pos, { x: Math.cos(angle) * len, y: Math.sin(angle) * len });
  drawLine(pos, end);
  if (depth === 0) return;                        // ← 止まる条件。これが無いと永遠に続く
  tree(end, angle + spread, len * 0.7, depth - 1);   // 左の枝（自分を呼ぶ）
  tree(end, angle - spread, len * 0.7, depth - 1);   // 右の枝（自分を呼ぶ）
}
tree({x: 0, y: 0}, PI / 2, 1, 8);   // depth 8 → 枝は 2^8 = 256 本

    深さを上げると、同じルールが小さなスケールで繰り返されます。線の本数がどう増えるか readout を見てください。

    再帰を読むコツ

    • 止まる条件を最初に探す。if (depth === 0) return; が無い再帰はバグ。
    • 「自分を呼ぶ」の中身を追わない。「小さい版の同じ問題を解いてもらう」と信じて読む。
    • 本数は「何回自分を呼ぶか」の depth 乗で増える。2回なら 2^depth、コッホは 4^depth。depth 10 で 100 万本。すぐ重くなるので、Houdini ではジオメトリの量に注意。

    CHAPTER黄金角：ひまわりの種は、なぜあの並び方なのか

    「n 番目の点を、角度 n × 137.5°、距離 sqrt(n) に置く」。たった2行で、ひまわり・松ぼっくり・多肉植物の配置になります。137.5° が特別なのは、「どれだけ回しても、前の点と重ならない角度」だから。

    // 点を n 個、螺旋状に置く（第5章：角度 → 矢印、前章：極座標）
const goldenAngle = 137.508 * PI / 180;   // ≒ 2.39996 ラジアン
for (let i = 0; i < n; i++) {
  const angle = i * goldenAngle;             // i 個目は、i 回ぶん回した角度
  const r     = Math.sqrt(i) * spacing;      // sqrt にすると密度が一定になる（面積が i に比例）
  points.push({ x: Math.cos(angle) * r, y: Math.sin(angle) * r });
}

    角度を 137.5° からほんの少しずらすと、腕（放射状の列）ができて隙間が空きます。黄金角だけが「隙間なく、腕もなく」埋まる。

    なぜ 137.5° なのか（ざっくり）

    角度が 90° なら 4 個ごとに同じ向きに戻って 4 本の腕になる。120° なら 3 本。「p/q 回転で元に戻る」角度は全部、腕ができて隙間が空く。一番「分数で表しにくい」回転 が黄金比（1.618...）ぶんの回転で、それが 137.5°。分数にならないから、いつまでも前の点と重ならない。植物は「新しい葉を、いちばん空いている方向に出す」を繰り返した結果、この角度に落ち着きます。

    CHAPTERボロノイ：「一番近い点はどれ？」だけで割れ目ができる

    Voronoi Fracture、キリンの模様、泡、乾いた泥。全部 「場所ごとに、いちばん近い種（seed 点）を探す」 だけ。同じ種に属する場所を集めると、細胞のような領域になります。

    // 場所 p にいちばん近い種の番号を返す。距離の比べっこ（第2章の length）
function nearest(p, seeds) {
  let best = -1, bestDist = Infinity;
  for (let i = 0; i < seeds.length; i++) {
    const d = length( sub(p, seeds[i]) );
    if (d < bestDist) { bestDist = d; best = i; }
  }
  return best;   // この番号で色を塗れば、ボロノイ図
}

    種（白い点）をドラッグ。「セル」は同じ種が最寄りの場所、「距離」は最寄りの種までの距離（Worley ノイズと呼ばれる模様）。境界線は「1番近い種と 2番目に近い種の距離がほぼ同じ場所」です。

    種の置き方で、模様の性格が決まる

    • ランダム（Scatter）：自然な破片。岩の割れ目。
    • 格子 + 少し乱す：均一な泡、ハニカムっぽい細胞。
    • 密度を偏らせる（Scatter の Density Attribute）：衝撃点のまわりだけ細かく割れる、あの表現。
    • 境界のところだけ取り出す（F2 − F1 が小さい所）：ひび割れ線、キリン、葉脈。

    CHAPTERセルオートマトン：「隣を見て決める」を繰り返すと生き物になる

    マス目のそれぞれが「隣のマスの状態」だけを見て、次の自分を決める。それを毎ステップ繰り返す。ルールは数行なのに、結果は予測できない模様と動き。Solver SOP の考え方そのものです。

    // ライフゲーム：各マスは「生」か「死」。周り 8 マスの生きている数で次を決める
function nextState(alive, neighbors) {
  if (alive)  return neighbors === 2 || neighbors === 3;   // 2〜3 なら生き残る。少なすぎ多すぎは死
  else        return neighbors === 3;                     // ちょうど 3 なら誕生
}

// 全マスについて、同時に更新する（重要：更新しながら読まない。前の状態は別に持つ）
for (let y = 0; y < H; y++) for (let x = 0; x < W; x++) {
  const n = countNeighbors(prev, x, y);        // 周り 8 マスを数える
  next[y][x] = nextState(prev[y][x], n);
}

    マスをクリックして生死を切り替え、再生してください。ルールを変えるとまったく別の世界になります。

    ルールの読み方：「生き残る数 / 誕生する数」。23/3 なら、生きているマスは隣が 2 か 3 で生き残り、死んでいるマスは隣が 3 で誕生。これを変えるだけで迷路やサンゴのような模様になります。

    Solver SOP の考え方は、これと同じ
    「前フレームの結果を入力にして、隣を見て、自分を更新する」。ライフゲームは 0/1 でしたが、値を小数にして「隣の平均に少し近づく」にすれば拡散（ぼかし）、「隣との差で加速する」にすれば波。次の章の反応拡散もこの形です。時間方向の再帰（前々章）と、隣を見る（この章）。この 2 つが「シミュレーション」の骨格。

    CHAPTER反応拡散：「にじむ」と「反応する」で、動物の模様ができる

    ヒョウの斑点、シマウマの縞、サンゴ、指紋。1952年にチューリング（コンピュータの父）が「2種類の薬品が にじみながら反応するだけ で模様になる」と予言し、本当にそうでした。前章のセルオートマトンを「小数」にしたものです。

    // 各マスに 2 つの値 u, v がある（2 種類の薬品の濃さ）。毎ステップこれを更新
function step(u, v, x, y) {
  const lapU = neighborsAverage(u, x, y) - u[y][x];   // 「隣との差」= にじむ方向（ラプラシアン）
  const lapV = neighborsAverage(v, x, y) - v[y][x];
  const uvv  = u[y][x] * v[y][x] * v[y][x];             // 反応：u が v に食われる量

  nextU[y][x] = u[y][x] + (Du * lapU - uvv + feed * (1 - u[y][x]));    // にじむ − 食われる + 補充
  nextV[y][x] = v[y][x] + (Dv * lapV + uvv - (feed + kill) * v[y][x]); // にじむ + 増える − 除去
}

    feed（補充）と kill（除去）のほんの少しの違いで、斑点・縞・迷路になります。クリックで v を垂らせます。

    読み解き

    • にじむ（拡散）：「隣との差」を少し足す。差があれば埋まる方向に動く。ぼかしと同じ。
    • 反応：u と v が出会うと v が増える。v が u より にじみにくい（Dv < Du）ので、v は塊を作る。
    • feed / kill：u を補充し、v を取り除く速さ。このバランスが「斑点か縞か」を決める。
    • 全部ローカルな計算。誰も「斑点を作ろう」とはしていないのに、斑点になる。
    Houdini でやるなら

    CHAPTER速度と加速度：シミュレーションの基本形は3行

    POP、RBD、Vellum、FLIP。どのソルバーも一番奥では 「速度に力を足す。位置に速度を足す。」 を毎フレーム繰り返しているだけ。第1章の「ベクトル＝移動」がそのまま動きになります。

    // 毎フレーム呼ぶ。dt = 1 フレームの時間（1/24 秒など）
function update(ball, dt) {
  const gravity = { x: 0, y: -9.8 };
  ball.v = add(ball.v, scale(gravity, dt));   // 1. 速度に加速度を足す（重力で下向きに速くなる）
  ball.p = add(ball.p, scale(ball.v, dt));    // 2. 位置に速度を足す（今の速度ぶん進む）

  if (ball.p.y < 0) {                        // 3. 床にめり込んだら
    ball.p.y = 0;
    ball.v.y = -ball.v.y * bounce;            //    上向きに跳ね返す（bounce = 0.8 なら少し勢いが減る）
  }
}

    画面をクリックするとボールが増えます。重力と跳ね返りを変えてみてください。矢印は速度ベクトル。

    「力」を足せば、何でも作れる

    • 風：一定の力を足す。v += wind * dt
    • 空気抵抗：速度と逆向きに、速度に比例した力。v = scale(v, 1 - drag * dt)
    • 引き寄せ：目標へ向かうベクトル（第1章の sub）を力にする。v += scale(normalize(sub(target, p)), k * dt)
    • ノイズで揺らす：第2章のノイズを力にする。POP Force の Noise はこれ。
    dt（時間刻み）が大きいと壊れる
    「今の速度で dt ぶん進む」は、速度が dt の間じゅう変わらないと仮定しています。動きが速いほど、dt が大きいほど、この仮定がウソになる。Houdini の Substeps は dt を細かく刻んでこの誤差を減らす設定。「めり込む」「爆発する」はたいてい dt が大きすぎ。

    CHAPTERバネと減衰：「戻ろうとする力」と「止まろうとする力」

    髪、布、ゼリー、追従カメラ、UI のバウンス。「揺れて、だんだん止まる」動きは全部 バネ（元の場所に戻る力）+ 減衰（速度を殺す力）。Vellum の Stiffness と Damping はこの 2 つの数字です。

    // 1 次元のバネ。x = 元の場所からのズレ、v = 速度
function update(s, dt) {
  const springForce = -stiffness * s.x;   // ズレと逆向きに、ズレに比例した力（フックの法則）
  const dampForce   = -damping   * s.v;   // 速度と逆向きに、速度に比例した力（ブレーキ）
  s.v += (springForce + dampForce) * dt;   // 前章と同じ：速度に力を足す
  s.x += s.v * dt;                         // 位置に速度を足す
}

    おもりをドラッグして離してください。右のグラフは位置の時間変化。stiffness で速さ、damping で止まりやすさが変わります。

    2 つの数字の読み方

    • stiffness 大：速く戻る、細かく震える。小さいと、ゆっくり大きく揺れる。
    • damping 0：永遠に揺れ続ける。大きすぎ：揺れずにヌルッと戻る（過減衰）。「1回だけ行き過ぎて戻る」くらいが気持ちいい（臨界減衰の少し手前）。
    • dt が大きいと、stiffness が大きいとき爆発する（前章の注意）。Vellum の Substeps / Constraint Iterations を上げる理由。

    CHAPTERベジェ曲線：「lerp の lerp の lerp」で曲線になる

    Illustrator のパス、アニメーションカーブ、フォント、Houdini の Curve SOP。全部ベジェ曲線で、中身は 第8章の lerp を入れ子にしただけ。制御点を触ると曲線が動く理由も、これで分かります。

    // 3 次ベジェ：制御点 4 つ (p0, p1, p2, p3) と t (0〜1) から、曲線上の点を返す
function bezier(p0, p1, p2, p3, t) {
  // 1 段目：隣どうしを lerp（3 点になる）
  const a = lerpVec(p0, p1, t);
  const b = lerpVec(p1, p2, t);
  const c = lerpVec(p2, p3, t);
  // 2 段目：また隣どうしを lerp（2 点になる）
  const d = lerpVec(a, b, t);
  const e = lerpVec(b, c, t);
  // 3 段目：最後の lerp（1 点になる）。これが曲線上の点
  return lerpVec(d, e, t);
}
// t を 0 → 1 に動かしながら bezier() を呼んで線でつなぐと、曲線

    制御点をドラッグ。t を動かすと、lerp の段階（灰 → 紫 → 緑）が見えます。曲線は p0 と p3 を通り、p1 と p2 には「引っ張られる」だけで通らない。

    知っておくと便利なこと

    • 曲線の 始点の向き は p0 → p1、終点の向き は p2 → p3。ハンドルの正体。
    • t を等間隔にしても、曲線上の点は等間隔にならない。Houdini の Resample が必要な理由。
    • アニメーションカーブの「イージング」は、横軸 t・縦軸 値 のベジェ曲線。第8章のイージングを、手で形作れるようにしたもの。
    • 制御点を増やす（4 点以上）と、lerp の段数が増えるだけ。ただし普通は 4 点の曲線をつなげる（NURBS / スプライン）。
    Houdini でやるなら

    CHAPTERベクトル場：「場所ごとの矢印」に粒子を乗せる

    煙の渦、髪の流れ、群れの動き、Advect by Volumes。空間の各点に「そこでの向き」を置いたものが ベクトル場。粒子はその矢印に従って進むだけ。第2章のノイズを「角度」に使うと、あの有機的な流れになります。

    // 場所 p での「流れの向き」を返す。ノイズ（第2章）を角度（第5章）にする
function field(p, time) {
  const angle = fbm(p.x * scale, p.y * scale + time * 0.2, 3) * PI * 4;   // ノイズ 0〜1 を角度に
  return { x: Math.cos(angle), y: Math.sin(angle) };                     // 長さ 1 の矢印
}

// 粒子は「今いる場所の矢印」の向きに進む（前々章の update と同じ形）
for (const pt of particles) {
  const dir = field(pt.p, time);
  pt.p = add(pt.p, scale(dir, speed * dt));
}

    薄い矢印がベクトル場、光る点が粒子。スケールを変えると渦の大きさが変わります。「渦」モードは curl ノイズ風（ノイズの「傾きを 90° 回した」向き）で、粒子が溜まらずに流れ続けます。

    ベクトル場の作り方いろいろ

    • ノイズ → 角度：上のコード。粒子が溜まる場所ができる（矢印が集まる所）。
    • curl ノイズ：ノイズの「傾き」を 90° 回した向き。{x: dNoise/dy, y: -dNoise/dx}。矢印が集まる場所が無いので、粒子が均一に流れ続ける。煙・流体っぽさの定番。
    • 中心へ渦巻き：第6章の極座標。「中心への向き」と「それを 90° 回した向き」を混ぜる。
    • ジオメトリから：法線や、Curve の接線を場にする（Attribute from Volume / Volume from Attribute）。髪の流れ、毛並み。

    CHAPTERLLM の中身も、ここまでと同じ数学でできている

    ChatGPT のような LLM（大規模言語モデル）は、魔法ではありません。ベクトル・内積・行列・補間。ここまでの章の道具だけで、骨格が説明できます。

    9-1. 単語はベクトル（埋め込み）

    LLM は、単語（正確にはトークン）1つを 数百〜数千個の数字のセット＝ベクトル にします。これを「埋め込み（embedding）」と呼びます。ポイントは 意味が近い単語ほど、近い場所に置かれる こと。

    単語を2つクリックすると、似ている度（normalize してから dot）が出ます。ここでは見やすく 2 次元にしていますが、本物は数千次元で、やることは同じです。

    // 似ている度（コサイン類似度）。第2章 + 第3章そのまま
function similarity(a, b) {
  return dot( normalize(a), normalize(b) );   // 1 に近いほど似ている
}

// 意味の足し算引き算（第1章）。「王 − 男 + 女」に一番近い単語を探すと「女王」
const q = add( sub(vec("王"), vec("男")), vec("女") );

    9-2. Attention：「どの単語を見るべきか」を内積で決めて、混ぜる

    文の中のある単語を理解するには、他のどの単語と関係が深いかを知る必要があります。「食べた」の意味は「誰が」「何を」で変わる。LLM の中心部品 attention は、これを 内積で「関係の深さ」を測り、その割合で単語ベクトルを混ぜる ことで実現します。

    注目する単語をクリック。他の単語との dot → softmax で「どれをどれだけ見るか」の割合が出ます。

    // 注目している単語 query が、文中の各単語 keys[i] をどれだけ見るか
for (let i = 0; i < keys.length; i++) {
  scores[i] = dot(query, keys[i]);          // 第3章：関係の深さ
}
const weights = softmax(scores);            // 合計が 1 になる「割合」に直す

// 割合どおりに単語ベクトルを混ぜる（第8章 lerp の親戚：重み付き平均）
let output = zero();
for (let i = 0; i < values.length; i++) {
  output = add(output, scale(values[i], weights[i]));
}
// output = 「文脈を混ぜ込んだ、新しい意味のベクトル」
    // softmax：数字の列を「合計 1 の割合」に直す。大きい数字ほど大きい割合に
function softmax(xs) {
  const es = xs.map(function(x) { return Math.exp(x); });   // exp で全部プラスに、差を強調
  const sum = es.reduce(function(a, b) { return a + b; }, 0);
  return es.map(function(e) { return e / sum; });
}

    本物では、query 用・key 用・value 用にそれぞれ 行列（第6章）で単語ベクトルを変換してから dot します。「どんな関係に注目するか」をその行列が決めていて、それを学習で調整します。

    9-3. 層 = 「行列で変形して、折り曲げる」

    第6章の行列は「空間ぜんぶを変形するレシピ」でした。ニューラルネットの1層は、まさに transform(m, p) です。ただし行列だけだと直線的な変形しかできないので、間に「折り曲げ」を挟みます。一番よく使う折り曲げが ReLU：「マイナスは 0 にする」だけ。

    function relu(v) {
  return { x: Math.max(0, v.x), y: Math.max(0, v.y) };   // マイナスを 0 に折る
}
function layer(m, p) {
  return relu( transform(m, p) );   // 変形 → 折り曲げ。これを何十回も重ねる
}

    円に並んだ点（白）を、行列で変形（青）し、ReLU で折り曲げる（黄）。折り曲げのおかげで「まっすぐでない」変形が作れます。

    学習 とは、この行列の中身（何百億個の数字）を「正解に近づく方向へ」少しずつ動かすことです。「どっちに動かすと結果がどれだけ変わるか」を測るのが微分ですが、概念としては「スライダーを少し動かして、良くなったらそっちへ進む」で十分です。

    まとめ：CG と LLM は同じ機械で動く
    • 単語 = ベクトル（第1章）、似ている度 = normalize + dot（第2・3章）
    • attention = dot で関係を測り、softmax で割合にし、重み付きで混ぜる（第8章の親戚）
    • 層 = 行列で変形 + 折り曲げ（第6章）
    GPU が「大量の dot と transform」を同時にやる機械だから、CG 用に作られた GPU が AI でも使われている。同じ数学だからです。
