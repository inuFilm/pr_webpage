    CHAPTERはじめに：エンジンの手順ではなく、原則を学ぶ

    ゲームのエフェクト（リアルタイム VFX）は、突き詰めると 「板に絵を描く」「板をたくさん飛ばす」「時間で見せる」 の 3 つでできています。この教材は、その 3 つをエンジンの名前を出さずに説明します。

    追加の比較実験：ちらつき・色の計算・帯の模様と等速移動。数学ページと往復して、見た目が崩れる理由を確かめられます。

    なぜエンジンの手順を書かないのか

    Unity / Unreal / Godot のどれで作っても、爆発は「一瞬のフラッシュ → 広がるリング → 飛ぶ火花 → 残る煙」です。変わるのはボタンの場所とノードの名前だけで、それは数年で入れ替わります。逆に、ここで扱う原則は 2016 年のフォーラム投稿でも今でも同じことが書かれています。

    「なぜそうするか」はここで学び、「どのボタンを押すか」は使うエンジンの現行ドキュメントで確認する。
    各章の操作はノードやモジュールの組み合わせとして読み替えられます。必ず1対1に対応するわけではありません。対応の付け方は Part 5の対応表 にまとめました。

    この教材の書き方ルール

    • Part 1 のシェーダーは GLSL（WebGL のシェーダー言語）で書きます。図の下にあるコードは 図で実際に動いているコードそのもの です。飾りの疑似コードではありません。
    • Part 2〜3 は JavaScript で、CGの数学を、数式なしで。 と同じ書き方（{x, y} の矢印、lerp()、noise()）です。
    • 数学が出てくる所には 数学 の印を付けて、数学アプリの該当章にリンクします。先にそちらを読んでも、後回しでも構いません。
    • 画像素材は一切使いません。炎も煙もフリップブックも、全部ブラウザの中で計算して作ります。だから「テクスチャの中身がどうなっているか」まで見えます。
    • WebGLの図はクリックで一時停止 / 再開できます。追加の比較実験は「自動再生」で操作します。
    // Part 1 のコードはこの形。uv（板の上の住所）から色を決める関数です
void main() {
  vec2 uv = v_uv;                         // 左下 (0,0) 〜 右上 (1,1)
  float n = fbm(uv * 4.0 - u_time);      // ノイズを時間で流す
  outColor = vec4(fireRamp(n), 1.0);      // 白黒に色を着ける
}

    全体の地図

    Part 1：1枚の板から始まる
    UV → 流す＋抜く → 歪み → ディゾルブ → 極座標 → ランプ → ブレンド → フレネルとソフトパーティクル → 頂点オフセット → ループ → 全部つなぐサンドボックス → 光を受ける板。エフェクトの「見た目」はほぼこの組み合わせ。
    Part 2：パーティクル
    発生と寿命 → 寿命カーブ → 速度と力 → ビルボードとリボン → リボンの UV → フリップブック → オーバードロー。板を「たくさん飛ばす」側の原則。
    Part 3：演出
    タイミング → 可読性 → 色の階層 → 要素の役割。技術より先に効いてくる、良し悪しを決める側の原則。
    Part 4：レシピ
    炎・煙・雷・斬撃・回復・衝撃波。新しい仕組みは出てこない。Part 1〜3 の部品を「何を、どの順で、どの数字で」組むか。
    Part 5：対応表
    この教材の章 → 数学アプリの章、GLSL / HLSL / VEX の関数名、ノード式エディタでの読み替え。
    原則 0：見た目が違うエフェクトの多くは、同じ部品の組み合わせでできている。
    炎・煙・オーラ・魔法陣は「ノイズを流して、マスクで抜いて、ランプで色を着ける」の 3 手順で全部作れます。部品を知ると、他人のエフェクトの構造が読めるようになります。それがこの教材の目標です。

    CHAPTERUV：板の上の「住所」から色を決める

    シェーダーは「このピクセルは板のどこか？」を受け取って「なら何色か」を返す関数です。その「どこか」が UV。左下が {u: 0, v: 0}、右上が {u: 1, v: 1} です。

    左の図は UV をそのまま色にしたもの（横 = 赤、縦 = 緑）。「流す速さ」を動かすと、板は動かないのに絵だけが流れます。それが「UV スクロール」です。

    


    覚えることは 2 つだけ
    

      
  
    • 絵を動かす = UV に足す。テクスチャは動かさず、読む場所をずらす。uv + speed * time が「スクロール」の全部です。
      • 
  
    • 1 を超えたら 0 に戻す = fract()。これで無限に流れます。テクスチャ側が「リピート」設定なら自動で同じことが起きます。
      • 

    

    この後の章で出てくる「歪み」「極座標」「フリップブック」は、全部 UV をどう加工してから読むか の話です。UV を加工する → 加工した UV で絵を読む。この順番を頭に入れておいてください。
    


    
  
    使っている数学
    
  fract() と繰り返しは 数学アプリ 13 章「mod と fract」。UV は 2 次元のベクトルなので 1 章「ベクトル」 の足し算そのものです。

    3 つの手順を分けて考える
    

    
  
    手順やっていること変えると何が変わるか
    
  
    1. 流すノイズの UV に時間を足す速さ・向き。炎は上、滝は下、渦は回転（5 章）
    
  
    2. 抜く「どこを残すか」の白黒（マスク）を掛ける形。炎は下が濃い縦長、玉は中心が濃い丸、リングは輪
    
  
    3. 切るsmoothstep(cut, cut + soft, v) でしきい値の下を捨てる密度と縁の硬さ。柔らかさ 0 に近づけると「切り絵」、大きくすると「もや」
    

    

    色は最後です。白黒で形が良ければ、色を変えるだけで炎にも毒霧にも氷にもなります（6 章「ランプ」）。まず白黒で作る、はこの先ずっと使う癖です。
    


    
  
    原則 1：白黒で形を作り、色は最後に着ける。
    
  実務でも、テクスチャは白黒のマスクとして描き、色はシェーダー側のランプで着けるのが基本です。1 枚の白黒素材が、色違いで何種類ものエフェクトに化けます。

    


    
  
    使っている数学
    
  ノイズと fbm は 12 章「ノイズ」。マスクの「中心からの距離で薄くする」は 15 章「フォールオフ」。smoothstep は 8 章「補間とイージング」 の仲間です。

    CHAPTER歪み：絵を変えずに、読む場所をゆがめる
    

    熱のゆらぎ、水面越しの景色、魔法の空間の歪み。これらは絵を加工していません。UV にノイズを足してから読む だけです。
    


    
  
    「ずらしベクトルを見る」を入れると、各ピクセルがどの方向に読みに行っているかが色で見えます（赤 = 右、緑 = 上）。市松は「本来の絵」の代わりです。
    
  
  
    
    
    
    
    
    
  
    

    

    


    ポイント
    

      
  
    • ノイズは 0〜1 なので 0.5 を引く。引かないと全体が右上にずれるだけになります。「ずらす」は矢印なので、正負が要ります。
      • 
  
    • 量は小さく。0.05〜0.1 で十分「ゆらぎ」に見えます。大きくすると絵が壊れます（それはそれで「空間の裂け目」に使えます）。
      • 
  
    • 歪みにもマスクを。「中心だけ歪める」の通り、歪みの量にマスクを掛けると、板の縁が歪んでいないので板の四角が見えません。
      • 
  
    • 2 章と組み合わせる。流した炎の UV をさらに歪めると、炎の「ゆらめき」になります。歪み用のノイズも流しておくのがコツです。
      • 

    


    
  
    使っている数学
    
  「位置に矢印を足す」は 1 章「ベクトル」 の足し算そのもの。ノイズを 2 枚使って矢印を作るのは 28 章「ベクトル場」 の考え方です。

    CHAPTERディゾルブ：ノイズとしきい値で「燃えて消える」
    

    キャラが灰になる、弾が霧散する、盾が砕ける。ノイズより「しきい値」を上げていく だけで、暗い所から順に消えていきます。しきい値のすぐ上に色を乗せると、燃えている縁になります。
    


    
  
    しきい値を左右に動かしてください。ノイズは動いていません。動いているのは「どこまで消すか」の数字だけです。
    
  
  
    
    
    
    
    
    
  
    

    

    


    2 つの関数が全部
    

      
  
    • step(th, n)：n が th 以上なら 1、未満なら 0。残すか消すか。
      • 
  
    • 1 - smoothstep(th, th + w, n)：th のすぐ上だけ 1 に近い。燃えている縁。w が縁の幅。
      • 

    

    ノイズの「細かさ」が消え方の性格です。粗いと「大きく崩れる」、細かいと「砂になる」。ノイズを 2 章の要領で流しておくと、消えながらゆらぎます。
    

    
  
    同じ仕組みの別名
    
  「エロージョン（侵食）」「アルファエロージョン」「バーン」はだいたいこれ。パーティクルの寿命でしきい値を動かせば、煙が「薄くなる」のではなく「ちぎれて消える」ようになります（Part 2 の寿命カーブと組み合わせる）。

    


    
  
    使っている数学
    
  しきい値で 0 / 1 にするのは 14 章「距離関数」 の「距離が 0 より上か下か」と同じ判定。縁の幅は 15 章「フォールオフ」。

    CHAPTER極座標：UV を「角度と距離」に変えると丸いものが作れる
    

    衝撃波のリング、渦巻き、光の筋、魔法陣。丸いエフェクトは UV を「中心からの角度」と「中心からの距離」に変換してから 2 章の手順を使います。
    


    
  
    まず「極座標を色で」を見てください。横方向（赤）が角度、縦方向（緑）が距離になっています。この新しい UV に対して「流す」を行うと、渦や放射になります。
    
  
  
    
    
  
    
  
    
    
    
    
  
    

    

    


    変換したら、あとは 2 章と同じ
    

    
  
    作りたいもの極座標での操作
    
  
    衝撃波リング距離 r 方向に「細い帯」を走らせる。abs(r - t) が小さい所だけ光る
    
  
    渦角度 a に距離 r を足してから（ねじれ）、r 方向にノイズを流す
    
  
    放射（光の筋）角度 a 方向だけのノイズ。r 方向には変化させない
    
  
    回転する魔法陣角度 a に時間を足す（a 方向のスクロール = 回転）
    

    

    
  
    角度には「つなぎ目」がある
    
  角度は 0 と 1 が同じ場所です。普通のノイズをそのまま角度に使うと、真左に縦の線（つなぎ目）が出ます。この図では fbmP（周期ノイズ）で「繰り返し回数」ぴったりで一周するようにしています。10 章「ループ」でもう一度出てきます。

    


    
  
    使っている数学
    
  16 章「極座標」 そのもの。atan() と length() は 5 章「sin / cos」 と 2 章「長さ」。

    CHAPTERランプ：0〜1 の数字を色に変える
    

    ここまでの図の「白黒」は、最後に ランプ（グラデーション） を通して色になっています。ランプは「0 なら黒、0.5 なら橙、1 なら白」のような対応表です。同じ素材でも、ランプを変えるだけで別のエフェクトになります。
    


    
  
    下端の帯がランプです。色を変えたり、プリセットを切り替えたりしてください。「白黒で見る」で着色前の素材に戻ります。
    
  
  
    
    
    
    
    
    
  
    
  
    
    
      
      
      
      
      
    
  
    

    

    


    ランプの設計で決まること
    

      
  
    • 明るさの並び。炎は「黒 → 赤 → 橙 → 黄 → 白」で、数字が大きいほど明るい。これは「中心（コア）が一番明るい」という 22 章の色の階層と同じことです。
      • 
  
    • 色数は 2〜3 色 + 白。「氷」プリセットは紺・水色・白だけ。増やすほど濁ります。
      • 
  
    • 位置は等間隔でなくてよい。この図は 0 / 0.33 / 0.66 / 1 に固定していますが、実際のツールでは位置も動かせます。炎の「白」は 0.85 以降だけ、のように狭く取るとコアが締まります。
      • 

    

    
  
    実装の形
    
  多くのエンジンで、ランプは「グラデーションのテクスチャを 1 本読む」か「カラーカーブのノード」です。ここでは mix と smoothstep で書きましたが、やっていることは 1 次元テクスチャの読み取りと同じです。

    


    
  
    使っている数学
    
  mix（lerp）と smoothstep は 8 章「補間とイージング」。色を 3 つの数字で扱うのは 1 章「ベクトル」 と同じです。

    CHAPTERブレンド：板を重ねるときの「足し算」と「混ぜ算」
    

    半透明の板を重ねるとき、後ろの色と新しい色をどう合成するかが ブレンドモード です。光るものは 加算、煙や埃は 通常（アルファ）。この使い分けが、エフェクトの「発光感」をほぼ決めます。
    


    
  
    同じ 5 枚の板を、合成方式だけ変えて重ねています。「明るい背景」にして加算を見てください。「順番を逆に」して、通常だけ結果が変わることも確かめてください。
    
  
  
    
    
    
    
    
  
    

    

    


    色管理を含めた違いは 色の計算 で比較できます。加算は発光表現の選択肢ですが、発光素材が必ず加算という意味ではありません。
    

    3 つの性格
    

    
  
    方式式向いているもの弱点
    
  
    通常（アルファ）mix(dst, src, a)煙・埃・水しぶき・破片。「物」描く順番で結果が変わる（ソートが要る）
    
  
    加算dst + src * a炎・光・火花・魔法。「光」明るい背景では見えない。重ねると白飛びする
    
  
    乗算dst * mix(1, src, a)影・焦げ跡・暗い霧明るくはできない
    

    

    
  
    原則 2：光は加算、物は通常。迷ったら「それは光っているか、光を遮っているか」で決める。
    
  加算は順番を気にしなくてよい（足し算は順序で変わらない）ので、パーティクルが大量にあるとき扱いやすい方式です。一方で、加算だけで組むと昼間の空で全部消えます。実務では「通常で下地の煙、加算で光」の 2 層が定番です。

    

    もう少し詳しく：事前乗算アルファ（premultiplied）

    1 枚のテクスチャで「加算っぽい所」と「通常っぽい所」を混在させたいとき、色にあらかじめアルファを掛けておく方式（事前乗算）を使います。式は dst * (1 - a) + src。src のアルファを 0 にして色だけ残すと、その部分は純粋な加算になります。炎（加算）と煙（通常）を 1 枚に描けるので、フリップブックでよく使われます。
    


    
  
    使っている数学
    
  mix(dst, src, a) は 8 章「補間」 の lerp。「足し算は順番で変わらない」は 1 章「ベクトル」 の足し算の性質です。

    CHAPTERフレネルとソフトパーティクル：「縁」をどう見せるか
    

    シールドやオーラは 縁だけ光る（フレネル）。煙の板は 地面と交わる線を消す（ソフトパーティクル）。どちらも「縁」を扱う定番で、これがあるかないかでエフェクトの品質が一段変わります。
    


    
  
    左の球はフレネル。「鋭さ」を上げると縁だけになります。右の煙の板は地面に刺さっていて、「フェード距離」が 0 だと交線がくっきり見えます。上げると消えます。
    
  
  
    
    
    
    
  
    

    

    


    フレネル：視線と面の向きの角度
    

    面の向き（法線）と視線がまっすぐ向き合っていれば dot = 1、直角なら dot = 0。1 - dot で「縁ほど 1」になり、pow() で鋭くします。シールド・ホログラム・ゴーストの「縁が光る」は全部これです。
    

    float fres = pow(1.0 - max(dot(normal, toCamera), 0.0), power);
// power 1: なだらか   3: 標準   6 以上: 縁の線だけ
    


    ソフトパーティクル：奥行きの差で薄くする
    

    煙の板が地面や壁に刺さると、交線が「板です」と白状してしまいます。板の奥行きと、その後ろにある物の奥行きの差 が小さい所を薄くすると、交線が消えます。エンジンでは「Soft Particles」「Depth Fade」という名前で用意されています。
    

    深度は同じ座標系・単位の線形距離に揃えます。深度バッファの生の値をそのまま距離として引かないでください。フェード距離0は無効として扱います。
    

    float fade = fadeDistance > 0.0 ? clamp((sceneDepth - particleDepth) / fadeDistance, 0.0, 1.0) : 1.0;
alpha *= fade;   // 後ろの物とほぼ同じ距離 → 0 に近づく
    


    
  
    使っている数学
    
  フレネルの dot(normal, view) は 3 章「内積」、法線は 4 章「外積」。奥行きは 7 章「3D と投影」。この図の球と地面は 14 章「距離関数」 の考え方で計算で描いています。

    CHAPTER頂点オフセット：色ではなく、形を動かす
    

    ここまでは「色を決める」側（フラグメントシェーダー）でした。もう 1 つ、頂点を動かす 側（頂点シェーダー）があります。旗、水面、揺れる草、脈打つ盾、衝撃波で歪む地面。形そのものが動くエフェクトです。

    CHAPTERループ：時間と空間の「つなぎ目」を消す
    

    環境のアンビエントエフェクト（たいまつ、湯気、オーラ）は何分でも回り続けます。時間のループ（何秒かで同じ絵に戻る）と 空間のタイル（並べても境目が出ない）は、どちらも「一周して元に戻る」を数学で保証する話です。
    


    
  
    「ただ流す」は下のバーが一周しても同じ絵に戻りません。「円を回ってループ」は戻ります。「タイルの比較」は左が普通のノイズ、右が周期ノイズを 2 × 2 に並べたものです。
    
  
  
    
    
    
    
  
    

    

    


    時間のループ：「直線」ではなく「円」で時間を進める
    

    時間をそのまま UV に足すと、時間は一直線に進むので戻ってきません。時間を 角度 にして、円の上の点 {cos, sin} を UV に足すと、一周で必ず元の場所に戻ります。半径が「一周の間にどれだけ変化するか」です。
    

    空間のタイル：ノイズの格子点を「割った余り」で選ぶ
    

    普通のノイズは格子点ごとに違う乱数を引くので、4 マス目と 0 マス目は別物です。mod(i, period) で格子点の番号を折り返すと、4 マス目 = 0 マス目になって境目が消えます。ノイズを重ねる（fbm）ときは、周期も一緒に 2 倍にしていくのがポイントです。
    

    
  
    フリップブックと「往復」
    
  連番（18 章）のループも同じで、最後のコマが最初のコマにつながる素材を作るか、最後まで行ったら逆再生する「ピンポン」で誤魔化します。ピンポンは折り返しで動きが一瞬止まるので、ゆっくりした素材にだけ向きます。

    


    
  
    使っている数学

    CHAPTER速度と力：粒の「動き」は 4 つの力の足し算
    

    パーティクルの動きは、生まれたときの 初速 と、毎フレーム足される 力 で決まります。重力・抵抗・乱流・渦。この 4 つで、噴水も火の粉も魔法の渦もできます。

    // 生まれるとき：扇（円錐）の中のランダムな向き
const a = PI / 2 + (rand() - 0.5) * spread;      // 真上 ± spread/2
p.vel = { x: Math.cos(a) * speed, y: Math.sin(a) * speed };

// 毎フレーム：力を速度に足し、速度を位置に足す
p.vel.y += gravity * dt;                          // 重力：下向きの力（正にすると「浮く」）
p.vel = scale(p.vel, 1 - drag * dt);              // 抵抗：速度を少しずつ削る
p.vel = add(p.vel, scale(curl(p.pos), turb * dt)); // 乱流：ノイズのカールを足す
p.pos = add(p.pos, scale(p.vel, dt));
    


    4 つの力の性格
    

    
  
    力何をするか使いどころ
    
  
    重力一定の向きに加速し続ける火花・破片・雨は下向き。火の粉・泡・煙は 負の重力（上向き） で浮かせる
    
  
    抵抗（ドラッグ）速度を毎フレーム少し削る「勢いよく出て、すぐ減速する」爆発の定番。抵抗なしだと等速で飛び続けて嘘っぽい
    
  
    乱流場所ごとに違う向きの矢印（ノイズのカール）を足す火の粉・煙・ホタル。「なんとなく揺れる」はこれ。矢印が渦を巻くので粒が集まりすぎない
    
  
    渦中心のまわりを回る向きに加速魔法・竜巻・吸い込み。「中心へ向かう力」を少し混ぜると集まりながら回る
    

    

    
  
    原則 5：初速は強く、抵抗で殺す。「速く出て、ゆっくり止まる」が気持ちいい。
    
  等速で動くものは機械的に見えます。初速を大きく、抵抗を強くすると、最初の数フレームで勢いを見せてから余韻に入ります。これは 20 章のタイミングと同じ形です。

    CHAPTERリボンの UV：曲がった帯の上でも、テクスチャは「まっすぐ」流れる
    

    剣の斬撃、ミサイルの煙、魔法の尾。曲がった帯にテクスチャを流すとき、大事なのは帯の形ではなく UV が平らでまっすぐに展開されていること です。UV さえ平らなら、帯がどう曲がっていてもテクスチャは帯に沿って流れます。
    


    
  
    制御点（丸）をドラッグして帯を曲げてください。右は「広げた UV」で、帯を平らに伸ばした状態。同じ (u, v) が同じ色になっていることを確かめてください。「UV を色で」で住所そのものが見えます。
    
  
  
    
    
    
    
    
    
    
  
    

    

    // 帯の上の位置 (u, v) → 色。u は根元 0 〜 先端 1、v は幅方向 0 〜 1
function tex(u, v, time) {
  const uu = u * tile - time * speed;            // u に時間を引く = 帯に沿って流れる（1 章のスクロール）
  const edge = 1 - Math.abs(v - 0.5) * 2;        // 帯の縁で薄くするマスク（2 章）
  return fireRamp(fbm(uu, v) * edge);
}
// 帯は「曲線に沿った小さな四角」の並び。各四角の (u, v) は曲線上の位置で決まる
for (i = 0; i < N; i++) for (j = 0; j < M; j++) fillQuad(quad(i, j), tex(i / N, j / M, time));
    


    この図は曲線のtをUVにしています。実距離で間隔を揃える方法は 曲線の距離 で比較できます。
    

    設計のポイント
    

      
  
    • UV は帯の長さ方向を u に。u = 0 が根元、u = 1 が先端。テクスチャの「流す」は u 方向にだけ掛けます。横方向（v）に流したいことはほとんどありません。
      • 
  
    • 帯の端は UV の端に揃える。先端が u = 1 ぴったりで終わっていないと、テクスチャの端で切れて見えます。
      • 
  
    • 先細りは形（メッシュ）で、消え方はテクスチャで。幅は帯の頂点で、透明度は v のマスクとディゾルブ（4 章）で作ると、両方を独立に調整できます。
      • 
  
    • 手で作るか、自動で作るか。この図は曲線から帯を「自動で」作っています（トレイル、16 章のリボン）。斬撃や魔法陣の飾りは、モデリングツールで帯のメッシュを「手で」作り、UV を平らに展開して使うのが定番です。どちらも UV の考え方は同じです。
      • 

    

    
  
    27 章「斬撃」でこの帯を使います

    使っている数学

    CHAPTERフリップブック：形が変わるものは「連番」で持つ
    

    爆発や煙のように 形そのものが時間で変わる ものは、ノイズを流すだけでは作れません。シミュレーションで作った連番を 1 枚のテクスチャに並べ、UV で「今のコマ」を切り出して見せます。これがフリップブック（スプライトシート）です。
    


    
  
    左のアトラスは、ブラウザ内で計算した「広がる火球」の 64 コマです。黄色い枠が今のコマ。fps を下げてカクつきを見てから「次のコマと混ぜる」を入れてください。
    
  
  
    
    
    
    
    
  
    
  
    

    

    // 今のコマ番号と、アトラス上の位置
const frame = Math.floor(time * fps) % (cols * rows);
const col = frame % cols, row = Math.floor(frame / cols);
// 板の uv（0〜1）を 1 コマぶんに縮めて、そのコマの位置へずらす（1 章の UV 加工）
const u = (uv.x + col) / cols;
const v = (uv.y + row) / rows;

// なめらかにする：次のコマと混ぜる（frame blending）
const f = time * fps, mixT = f - Math.floor(f);
const nextFrame = (frame + 1) % (cols * rows); // ループ再生。単発なら最後のコマで止める
color = lerp(sample(frame), sample(nextFrame), mixT);
    


    フリップブックの原則
    

      
  
    • コマ数と解像度はトレードオフ。1 枚のテクスチャの中で、8 × 8 なら 1 コマは 1/8 の解像度です。動きが速いものはコマ数、静かなものは解像度に振ります。
      • 
  
    • コマ間の補間で少ないコマを誤魔化す。「次のコマと混ぜる」は最も単純な方法（クロスフェード）。さらに「モーションベクター」（各ピクセルが次のコマでどこへ動くかの矢印）を持たせると、混ぜるのではなく 歪めて つなぐので、コマを大きく減らせます。3 章の歪みの応用です。
      • 
  
    • チャンネルに詰める。白黒の連番なら、R・G・B・A の 4 チャンネルに別々の連番を入れられます。8 × 8 × 4 = 256 コマが 1 枚に入ります。この図の「チャンネルに詰める」は R = 火球、G = 煙、B = 衝撃波です。アトラス自体は色が混ざって見えますが、シェーダーで 1 チャンネルだけ読めば元に戻ります。
      • 
  
    • 単発とループで終わり方を変える。単発は最後を透明にするか、寿命カーブで薄くしてから止めます。ループは最後と最初の形・動きをつなぎます。毎周透明にすると、かえって点滅する場合があります。
      • 

    

    
  
    素材はどこから来るか
    
  実務では Houdini / Blender / EmberGen などでシミュレーションし、連番でレンダーして並べます。この教材では原則に集中するため、ブラウザ内の fbm で計算しています。Houdini の COP で焼く方法は技術メモの「COP でフリップブックを焼く」系の記事を参照してください。

    


    
  
    使っている数学
    
  コマ番号の floor と % は 13 章「mod と fract」。コマ間の混ぜ合わせは 8 章「補間」。

    CHAPTERオーバードロー：「何枚描くか」より「何回塗るか」
    

    リアルタイム VFX が重くなる一番の理由は、ポリゴン数でもテクスチャの大きさでもなく、同じピクセルを何回も塗り直すこと（オーバードロー）です。半透明の板は後ろを隠せないので、重なった分だけ全部塗ります。
    


    
  
    ヒートマップは「そのピクセルを何回塗ったか」（青 1 回 → 赤 8 回以上）。「大きく少なく」と「小さく多く」で、塗った総量がどう変わるか比べてください。
    
  
  
    
    
    
    
    
    
  
    
  
    

    

    // 塗るコスト ≈ 各板の面積の合計（重なっていても、そのたびに塗る）
fill = sum(sprite.w * sprite.h) / (screen.w * screen.h);   // 画面の何倍塗ったか
// 板の数を 2 倍にしても、大きさを半分にすれば面積は 1/4 → 合計は半分
    


    軽くする手はだいたい 4 つ
    

      
  
    • 板を小さくする。面積は「大きさの 2 乗」なので、大きさ半分で面積は 1/4。数を減らすより効きます。
      • 
  
    • 透明な角を切る。丸い絵の入った四角い板は、角の 20〜30% が「透明なのに塗っている」領域です。八角形に切るとその分が消えます（カットアウトメッシュ）。
      • 
  
    • 画面に近づけない。カメラの目の前で爆発すると、1 枚の板が画面全体を覆います。同じエフェクトでも距離で 100 倍重くなり得ます。
      • 
  
    • 数を減らして、1 枚を「頑張らせる」。フリップブック（18 章）や歪み（3 章）で 1 枚の情報量を増やし、板の数を減らします。
      • 

    

    
  
    原則 6：面積で数える。「何個出しているか」ではなく「画面の何倍を塗ったか」。
    
  「重い」と言われたら、まず一番大きい板を探します。小さい板 100 枚より、大きい板 3 枚が重いことはよくあります。

    


    
  
    使っている数学
    
  「大きさ半分で面積 1/4」は 6 章「行列」 のスケールと面積の関係。ヒートマップは 23 章「セルオートマトン」 と同じ「格子に数を溜める」計算です。

    CHAPTERタイミング：技術より先に効いてくるもの
    

    手法を覚えれば作れますが、良し悪しを決めるのはタイミングです。ヒットも爆発も魔法も、時間の形は 溜め → 衝撃 → 余韻。この 3 つの長さと、要素をいつ出すかで、ほとんどが決まります。
    


    
  
    右上のグラフは「画面の明るさ」の時間変化です。良いヒットは「急に上がって、なだらかに下がる」形。プリセットで極端な例と比べてください。時間スライダーで 1 フレームずつ送れます。
    
  
  
    
  
    
    
    
    
    
  
    
  
    
    
  
    
  
    
    
    
    
    
    
  
    

    


    3 つの区間
    

    
  
    区間長さの目安やること間違えると
    
  
    溜め（予備動作）0.1〜0.4 秒。強い技ほど長い外から中心へ集める。小さく暗く。「来るぞ」を知らせる無いと唐突。長すぎると間延び
    
  
    衝撃2〜4 フレーム（0.05〜0.15 秒）フラッシュ・リング・火花を 同時に、一番大きく明るく。一番情報量が多い瞬間長いと「ぼやけたヒット」。一瞬だから強く見える
    
  
    余韻0.5〜2 秒。衝撃の 5〜10 倍煙・残り火・破片が 減速しながら 消えていく。要素ごとに消える時刻をずらす短いと「突然消える」。全部同時に消えると「パッ」と無くなる
    

    


    
  
    原則 7：足すより、延ばす。勢いが途切れるなら、要素を増やすのではなく既にあるものの寿命を延ばす。
    
  「火花を出し続ける（悪い例）」を入れてみてください。にぎやかにはなりますが、衝撃の「ドン」が薄まり、いつ終わったのか分からなくなります。初学者がやりがちな「情報を足して豪華にする」の逆で、既存の火花の寿命を延ばすほうがまとまります。

    

    
  
    間隔は「口で音を出して」測る
    
  要素と要素の間隔をどれくらい空けるか迷ったら、そのエフェクトの音を口で出してみます。「スッ…ドン！…ジュワァ」。息を吸うのにかかる時間、口の形を変えるのにかかる時間が、要素間に最低限必要な間隔にかなり近い。「残り火の遅れ」はそのための「ひと息」です。

    


    
  
    使っている数学
    
  各要素の減衰は 8 章「イージング」（衝撃は easeOut、煙は easeOutCubic）。明るさのグラフは各要素の「強さ × 残り」の足し算です。

    CHAPTER可読性：きれいなエフェクトと、ゲームとして成立するエフェクトは別
    

    対戦ゲームの VFX 担当者が繰り返し言うのは、プレイヤーが状況を読めなくなるエフェクトは、どれだけ美しくても採用されない ということです。「派手すぎず、コントラストが強すぎない」が実務の基準になります。
    


    
  
    ゲーム画面の中にヒットを置いています。「シルエット」「ぼかし」「白黒」は可読性のチェック方法です。これで何が起きているか分かれば、本番でも分かります。「全部同じ大きさ」で悪い例を見てください。
    
  
  
    
    
    
    
    
    
    
  
    
  
    
    
    
    
  
    

    


    可読性を作る 3 つの道具
    

      
  
    • 大・中・小。主役（フラッシュとリング）は 1 つ大きく、脇役（火花）は中くらいを十数個、粒（残り火）は小さく多く。「全部同じ大きさ」にすると、目がどこを見ればいいか分からなくなります。面積の目安は 6 : 3 : 1。
      • 
  
    • シルエットで読める形。塗りつぶしにしても「何が起きたか」が分かる形にします。丸いリング = 衝撃、放射状の線 = 爆発、上に伸びる形 = 上昇、と形だけで意味が伝わります。
      • 
  
    • 明るさの差は、背景との差。暗い背景で作った加算エフェクトは、明るい背景で消えます（7 章）。どちらの背景でも読めるように、通常ブレンドの下地（暗い煙や縁取り）を持たせます。
      • 

    

    
  
    原則 8：焦点は 1 つ。エフェクトの中で「一番見せたいもの」を決めて、他はそれを邪魔しない。
    
  展開の速い場面で、副次的な要素はノイズになって焦点を奪います。「これを足したら主役が見えにくくならないか」を毎回問い直します。

    

    
  
    チェックの仕方
    
  ぼかす（目を細める）、白黒にする、シルエットにする、再生速度を落とす、そして 実際のゲーム画面に置く。単体のプレビューで良く見えても、地面・キャラ・UI の上に置くと読めないことは多い。この図に「プレイヤー」と「敵」を置いているのはそのためです。

    


    
  
    使っている数学
    
  「大・中・小」は面積の比なので 6 章「行列」 のスケール。ぼかしと白黒は画像処理ですが、白黒化の式（0.299 R + 0.587 G + 0.114 B）は 3 章「内積」 の重み付き和です。

    


    
  
    ヒットエフェクトが「派手すぎて敵の位置が分からない」と言われた。最初にやることは？
    
  
    
    
    
    
  
    
  
    

    

    



    

    CHAPTER色の階層：明るさの順番で「光っている」に見せる
    

    この作例では コア（ほぼ白）→ 中（鮮やかな色）→ 縁（暗い色） の明るさの差で発光を表現します。これはスタイライズの一例です。中心が暗いシールドや色の濃い光などもあり、背景・露出・作品の表現に合わせて階層を設計します。
    


    
  
    「明るさだけ」を入れて、コアが一番明るいことを確かめてください。プリセットの「逆（悪い例）」はコアが暗く縁が明るい。同じ形なのに光って見えません。
    
  
  
    
    
    
    
    
    
    
  
    
  
    
    
      
      
      
      
      
    
  
    

    

    


    色を決める順番
    

      
  
    1. 明るさの並びを先に決める。コア > 中 > 縁。「明るさだけ」で見て、この順になっていなければ色相をいじっても直りません。
      2. 
  
    2. 色相は 1〜2 色。「中」の色がそのエフェクトの色です。縁は「中」を暗くした色か、その補色（橙に対して紫、水色に対して紺）。3 色目を足すと濁ります。
      3. 
  
    3. コアは白に寄せる。真っ白でなくてよいが、彩度を落として明るく。加算で重ねると自然に白くなるので、コアの色は「中」の薄い版でも足ります。
      4. 
  
    4. ランプ（6 章）に落とす。この 3 色を 6 章のランプに並べれば、白黒素材に着けられます。ランプの右端がコア、左端が縁です。
      5. 

    

    
  
    原則 9：色より先に明るさ。明るさの順番が正しければ、色相は後からいくらでも変えられる。
    
  白黒で作って色は最後（原則 1）と同じことを、色の設計の側から言っています。

    


    
  
    使っている数学
    
  中心からの距離で 3 段に分けるのは 15 章「フォールオフ」、色の混ぜ合わせは 8 章「補間」。明るさの計算は 3 章「内積」。

    


    
  
    青い光のエフェクトが「塗った丸」に見える。まず確認することは？
    
  
    
    
    
    
  
    
  
    

    

    



    

    CHAPTER要素の役割：1 つのヒットは 8 つの部品でできている
    

    ここまでの部品を全部使って、ヒットエフェクトを組み立てます。要素を 1 つずつ入れたり切ったりして、それぞれが何を担当しているか を確かめてください。
    


    
  
    「全部切る」から 1 つずつ足していくのがおすすめです。フラッシュだけ、リングだけ、では何が足りないか。煙を切ると「終わり」が無くなることに気づくはずです。
    
  
  
    
    
    
    
    
    
    
    
    
    
  
    
  
    
    
    
    
    
  
    

    


    要素と役割
    

    
  
    要素役割区間使った部品
    
  
    溜め予告。「来る」を知らせる溜め内向きの速度（15 章）、小さく暗い光
    
  
    フラッシュ主役。衝撃の瞬間そのもの衝撃（2〜4 フレーム）加算の丸（7 章）、コアが白（22 章）
    
  
    衝撃波リング衝撃の「大きさ」と「方向」を伝える衝撃〜余韻のはじめ極座標のリング（5 章）、急速に広がって薄くなる（14 章）
    
  
    火花勢い。エネルギーが飛び散る衝撃〜余韻バースト（13 章）、重力と抵抗（15 章）、ストレッチ（16 章）
    
  
    煙余韻。「終わり方」を作る余韻通常ブレンド（7 章）、大きくなって薄くなる（14 章）
    
  
    残り火余韻の中の小さな動き。「ひと息」置いてから余韻（遅れて）小さく多く（21 章）、上向き重力（15 章）
    
  
    周囲の光エフェクトを「場所」につなぐ。地面や壁を照らす衝撃ライト、または加算の大きな薄い板
    
  
    破片 / 焦げ跡「物が壊れた」「跡が残った」の説得力余韻〜残るメッシュ（16 章）、乗算のデカール（7 章）
    

    

    
  
    原則 10：二次要素は「同じ種類を増やす」のではなく「違う性質のもの」を足す。
    
  火花が足りないと感じたとき、火花を増やすのではなく、性質の違う要素（渦を巻く煙、遅れて出る残り火）を足すほうが、埋まりつつ独自性が出ます。そして終わり方（煙がどう消えるか）まで設計して初めて完成です。

    

    
  
    プレースホルダーの作り方
    
  実務で最初に作るのは仮のエフェクトです。そのとき「最終的な命名にしておく」「呼び出し元（アニメーションやイベント）に紐づけておく」「向きと大きさを合わせておく」と、後からテクスチャと色を差し替えるだけで完成品にできます。この章の「全部入れる」状態が、その仮組みに相当します。

    


    
  
    「煙」を切ると何が失われる？
    
  
    
    
    
    
  
    
  
    

    

    



    

    CHAPTERレシピ 1：炎 = 本体 + コア + 火花 + 根元の光
    

    ここからは 新しい仕組みは出てきません。前の章の部品を「何を、どの順で、どの数字で」組むかだけです。まず一番よく使う炎から。たき火・たいまつ・燃える瓦礫は全部これの変形です。
    


    
  
    「表示」で層を 1 つずつ見てください。本体だけでは平たく、コアを加算で足すと「熱さ」が出て、火花で空気感、根元の光で場所につながります。
    
  
  
    
    
    
    
    
    
  
    

    

    


    レシピ
    

    
  
    層部品設定の要点章
    
  
    本体流す + 抜く、炎ランプ縦長マスク、上向きに流す、ノイズは縦に間延び（vec2(4, 2.5)）。しきい値は中くらい2, 6
    
  
    コア同じノイズ、狭いマスク、高いしきい値本体より 狭く・短く・少し速く。色はほぼ白。加算で重ねる7, 22
    
  
    揺らぎ歪み上へ行くほど強く（× uv.y）。根元は揺れない3, 9
    
  
    火花上向き重力の粒、寿命で減光少なめ（10 個前後）、寿命 2〜4 秒、横に少し揺れる13, 15
    
  
    根元の光周囲の光橙の柔らかい丸。地面や壁を照らして「場所」につなぐ23
    

    

    調整のコツ

    CHAPTERレシピ 3：雷 = ギザギザの線 + 3 段の光 + 一瞬のタイミング
    

    雷はテクスチャではなく 線 でできています。線をギザギザにする（中点変位）、線を太さ違いで 3 回重ねる（色の階層）、そして 2〜3 フレームだけ光る。形より時間が効くエフェクトです。
    


    
  
    「残像」を 0 にすると、光っている時間が本当に 2〜3 フレームしかないことが分かります。それでも「見えた」と感じるのが雷です。「再ストライク間隔」を短くすると連続落雷になります。
    
  
  
    
    
    
    
    
    
    
    
  
    

    

    // 中点変位：線分の真ん中をランダムに横へずらし、それを繰り返す（cgmath 20 章のフラクタル）
function makeBolt(a, b, depth, jag) {
  let pts = [a, b];
  for (d = 0; d < depth; d++) {
    const next = [pts[0]];
    for (i = 0; i < pts.length - 1; i++) {
      const mid = midpoint(pts[i], pts[i + 1]);
      const off = (rand() - 0.5) * length(pts[i], pts[i + 1]) * jag;   // 短い線分ほど小さくずれる
      next.push(add(mid, scale(normal(pts[i], pts[i + 1]), off)), pts[i + 1]);
    }
    pts = next;
  }
  return pts;   // depth 6 で 65 点
}

    CHAPTERレシピ 4：斬撃 = 弧の帯 + 白いコア + 走ってから消える
    

    斬撃は「帯（17 章）」の代表的な使い方です。弧に沿って 先端が走り、尾が追いかけ、走り終わったらディゾルブで消える。0.3 秒前後の短いエフェクトなので、再生速度を落として見てください。
    


    
  
    再生速度 ×0.25 で始まります。先端（easeOut で速く出て減速）、尾（先端より遅れて追う）、消え方（走り終わってから）の 3 つの時間を見てください。
    
  
  
    
    
    
    
    
    
    
  
    

    

    // 時間 t（0〜1）から、帯のどこが見えているかを決める
head  = easeOutCubic(t);                  // 先端：はじめ速く、減速して止まる（14 章）
tail  = head - length;                     // 尾：先端から一定の長さだけ後ろ
erode = max(0, t - 0.9) * 1.2;             // 走り終わったら、しきい値を上げて消す（4 章）
for (u of 帯の位置) {
  if (u < tail || u > head) continue;      // 見えている範囲だけ
  if (fbm(u, v) < erode) continue;         // ディゾルブ
  width = maxWidth * sin(along * PI);       // 尾と先端で細く、真ん中で太く
  color = mix(edgeColor, white, centerness); // v = 0.5 が白、縁が色（22 章）
}

    CHAPTERレシピ 5：回復 = 衝撃のない、上がって消えるループ
    

    回復・バフ・詠唱は、ヒットと逆の時間構造です。溜めも衝撃もなく、上昇と減衰だけ。柔らかい山のカーブ、2 色 + 白、ループ。「良い効果」であることを、形と時間で伝えます。

    CHAPTERレシピ 6：衝撃波 = 広がるリング + 歪み + 土埃 + 跡
    

    着地、爆発、強攻撃のヒット。衝撃波は 極座標のリング を「光」ではなく 歪み として使うのが定番です。空気が押される見た目は、背景の UV をリングの位置で外へ押し出すだけで作れます。
    


    
  
    「歪みだけ」にすると、光るものが何も無いのに「何かが広がった」と分かります。「リングと土埃だけ」と比べてください。完成は両方の足し算です。
    
  
  
    
    
    
    
    
  
    

    

    


    レシピ
    

    
  
    要素部品設定の要点章
    
  
    リングの位置極座標の r、easeOut で広がる最初の数フレームで半分以上進む。広がるほど薄く5, 14
    
  
    歪みUV を中心から外へ押す押す量 = リングの断面 × 強さ × 残り。光らせなくても「衝撃」が伝わる3
    
  
    光る縁加算の細い帯一瞬だけ。残りの 2 乗で急に消す7, 20
    
  
    土埃リングの内側をノイズで抜いた輪角度方向は周期ノイズ（つなぎ目なし）。リングより少し遅れる2, 10
    
  
    跡中心を乗算で暗く残る。「何かが起きた場所」を示す7, 23
    

    

    調整のコツ
    

      
  
    • 歪みは小さく。0.03〜0.06 で十分。大きいと背景が壊れて「バグ」に見えます。
      • 
  
    • リングは薄く速く、土埃は厚く遅く。同じ速さで同じ厚さだと 1 本の輪にしか見えません。性質の違う 2 つの輪をずらす（原則 10）。
      • 
  
    • 実務では「歪みリング」は専用のブレンド（屈折 / スクリーン歪み）で、背景を読んでずらす板として作ります。この図の「背景の UV をずらす」と同じことをエンジンがやってくれます。

    CHAPTERサンプリング：細かい模様がちらつく理由
    

    雷の細い線、魔法陣の縞、ディゾルブの縁。近くではきれいでも、小さく表示するとちらつくのは、画素が模様を拾いきれない場合があるからです。
    

    

    模様を細かくしてから位相を動かしてください。同じ標本数でも「点で読む」と「幅で平均する」では見え方が変わります。
    


    

    

    「点」ではなく「画素が覆う範囲」を考える
    

    幅の中に f 周の正弦波があり、N 個の等間隔な標本で読むとします。元の波を区別するには f が N/2 より小さい必要があります（帯域制限された信号を前提とするナイキスト条件）。境界ちょうども位相によって情報が失われます。
    

    デモの下段は、各画素の幅で正弦波を平均した結果です。細部を灰色に近づけることで偽の模様を弱めます。失われた細部を復元する処理ではなく、箱型平均だけですべてのエイリアシングを除けるわけでもありません。
    

    

    上はこの図で使う平均値の計算です。正弦波だから積分を直接計算でき、一般の画像では複数の標本やフィルターを使います。
    

    VFXで調整する順番
    

    • まず表示サイズと模様の細かさを合わせる。遠景ではノイズの細部やリング本数を減らす。
    • テクスチャの縮小ではミップマップを使う。手続き模様には自動でミップが付かないので、画素の幅に応じて細部を減らす。
    • 境界の滑らかさには fwidth などの画面上の変化量を使える。WebGL 1では微分の拡張が必要。この図はCPUで計算するため不要。
    • 時間方向も同じ。発光の点滅が速すぎるとフレーム間で見落とす。空間の平均だけで時間方向まで解決するわけではない。

    CHAPTER色の計算：半分の光はどんな灰色？
    

    発光や煙の合成は、RGBを足すだけで終わりではありません。保存・表示用のsRGB値と、光の量に比例した値を区別すると、暗い混ざり目の原因が読めます。
    

    

    白の割合を0.5にすると違いがよく見えます。左右は同じ黒と白から作っています。
    


    

    

    読む → 線形に戻す → 計算 → 表示用に戻す
    

    黒0と白1を光の量で半分ずつ混ぜると、線形値は0.5、表示用のsRGB値は約0.735です。sRGB値を直接0.5にすると、その線形値は約0.214。この違いが左右の灰色の差です。
    

    

    この図で使うsRGB変換です。一般の色はR・G・Bそれぞれを decode し、補間や合成後に encode します。入力は0〜1のsRGB、計算も同じ色域を前提としています。芸術的なグラデーションでは別の色空間を選ぶこともあります。
    

    色とデータを区別する
    

    • 色として保存した画像にはsRGB変換が必要な場合がある。描画環境が自動変換しているときは二重に変換しない。
    • マスク・法線・深度などの数値データは、見た目の色ではない。意図せずsRGB変換すると値を変えてしまう。
    • アルファは通常、色のsRGB変換の対象にしない。事前乗算アルファは rgbPremultiplied = rgbLinear * alpha。背景との合成も線形で行う。
    • HDRは1より大きな光の値も保持する。露出・トーンマッピング・ブルームは別の処理。この比較図は0〜1のSDRで、ブルームやHDRを再現していない。
    

    既存のランプ・ブレンドの図は計算構造を見せる簡略例です。実際の色管理を含めた見た目が、すべてのレンダラーで一致するという意味ではありません。

    CHAPTER曲線の距離：tを等間隔にしても等速ではない
    

    帯の根元から先端へUVを並べても、模様の間隔まで揃うとは限りません。曲線のパラメータを使うか、実際の長さを使うかで、模様の伸縮と流速が変わります。
    

    

    青い点は12等分の目印、黄色は現在位置です。曲線の形を変えてから再生すると、上の点だけ速さが変わる様子が見えます。
    


    

    

    距離を足した表から逆引きする
    

    1. 曲線上の点を細かく取る。
    2. 隣り合う点の距離を足して「t → 累積距離」の表を作る。
    3. 進みたい距離を表で探し、その間のtを補間して位置を求める。
    

    

    この図の計算に使う関数です。折れ線での近似なので、鋭く曲がる場所では分割数を増やす必要があります。同じ距離を進む点でも、曲がり角を挟んだ直線距離は短く見えることがあります。
    

    帯のUVに使うなら
    

    u = 累積距離 / 全長 は帯全体に模様を収める方法。帯が伸びれば模様も伸びます。u = 累積距離 / 1模様の長さ は世界の長さで密度を揃える方法。帯が伸びると繰り返し回数が増えます。どちらを使うかは演出によります。
    

    この図は固定された曲線を一定の周回時間で進む比較です。曲線そのものが変形するときの世界速度や、3Dで帯がねじれないフレームの計算は含みません。
